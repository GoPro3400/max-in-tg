# Участие В Разработке

Личный проект одного человека, self-hosted мост между веб-сессией MAX и Telegram. PR
приветствуются. Исходный код хранится в Git; секреты и runtime-состояние в Git не
попадают.

---

## Что Коммитить

| Путь | Описание |
|------|----------|
| `src/` | Исходный код |
| `tests/` | Unit- и интеграционные тесты |
| `docs/` | Документация |
| `scripts/` | Вспомогательные скрипты |
| `Dockerfile` | Production image |
| `docker-compose.yml`, `docker-compose.prod.yml` | Compose конфигурации |
| `package.json`, `package-lock.json` | Зависимости и скрипты |
| `.env.example` | Шаблон переменных |
| `README*.md` | Документация верхнего уровня |
| `CHANGELOG.md` | История изменений |
| `CONTRIBUTING.md` | Правила участия |
| `SECURITY.md` | Как сообщить об уязвимости |

## Что НЕ Коммитить

| Путь | Причина |
|------|---------|
| `.env` | Содержит секреты |
| `data/` | Runtime данные и Chrome profile |
| `tmp/` | Временные медиа |
| `logs/` | Логи и диагностика |
| `node_modules/` | Устанавливается через npm |

Все эти пути уже закрыты в `.gitignore`.

## Рабочий Процесс

### Ветки

```bash
fix/<short-change-name>
feat/<short-change-name>
```

### Правила

1. Форк → ветка → pull request в `main`
2. Делать изменения небольшими и понятными для ревью
3. Перед коммитом — синтаксические проверки и `npx vitest run`
4. Обновлять документацию при изменении переменных, деплоя или UX
5. Обновлять `CHANGELOG.md` (раздел `[Unreleased]`)

`.github/workflows/ci.yml` прогоняет `npm test` на каждом PR — запусти `npx vitest run`
локально перед отправкой.

## Приоритеты Ревью

Проверять изменения в порядке критичности:

| # | Приоритет | Описание |
|---|-----------|----------|
| 1 | **Безопасность** | Риск отправить сообщение не тому человеку |
| 2 | **Надёжность** | Потеря или дублирование сообщений |
| 3 | **Хрупкость** | Max Web селекторы могут сломаться |
| 4 | **Секреты** | Telegram-права и хранение credentials |
| 5 | **Деплой** | Docker/VPS deployability |
| 6 | **Edge cases** | Конвертация медиа, таймауты |

> Если изменение может привести к отправке сообщения в неправильный Max-чат → **fail closed**: не отправлять и сообщить об ошибке.

## Локальная Проверка

Нужен **Node.js 20** — на нём собирается образ (`node:20-bookworm-slim`) и работает CI.
На Node 18 нативная сборка `better-sqlite3` может упасть, и это будет выглядеть как
поломка проекта.

### Минимум (синтаксис)

```bash
node --check src/index.js
find src -name "*.js" -print -exec node --check {} \;
```

### Тесты

```bash
npm ci        # ровно то, что зафиксировано в package-lock.json — как в CI и в Docker
npx vitest run
```

### Полная сборка

```bash
docker compose -f docker-compose.prod.yml build
```

> Не запускайте production stack с реальными credentials, если `.env` не настроен под нужный аккаунт.

## Важные Соглашения

**Документация**

- Русская документация — основная. `README.md` — краткая русская версия и главная
  страница репозитория, `README.ru.md` — полная русская, `README.en.md` — английская.
  Изменение, затрагивающее UX или переменные, правится во всех трёх
- Пошаговая инструкция для новичков живёт в `docs/SETUP_GUIDE.md`, разбор медиа и
  селекторов — в `docs/MEDIA_PIPELINE.md`

**Безопасность и приватность**

- Источник правды по селекторам — **живой MAX Web**. Прежде чем добавлять или менять
  селектор, посмотри реальный DOM залогиненного клиента, а после изменения прогони
  `/check`
- Если есть риск отправки не тому человеку — блокировать отправку (fail closed).
  То же для тем: не удалось создать тему — сообщение не уходит в общий чат
- QR входа в MAX — это учётные данные: кто отсканирует, тот привяжет своё устройство к
  аккаунту. Только в личный чат владельца, никогда в группу
- Не логировать текст сообщений и содержимое QR: через мост идёт реальная переписка
  живых людей. Дампы диагностики редактируются (`sanitizeDiagnosticHtml`) — не добавляй
  путей, которые обходят редакцию
- `maxLock` **не реентрантен**: вложенный `maxLock.run()` внутри уже захваченного замка
  вешает мост навсегда
- Не ломать Telegram Topics модель ради удобства
- Селекторы могут измениться — делать их конфигурируемыми через `.env` и добавлять
  новые ключи в `.env.example`
