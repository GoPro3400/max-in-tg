> **Прочитай это первым.** Это неофициальная автоматизация: публичного API у MAX нет,
> поэтому мост открывает настоящий веб-клиент web.max.ru в настоящем Chromium **на твоём
> сервере**, под **твоим** аккаунтом MAX, со stealth-плагином, задача которого — не дать
> веб-клиенту распознать в нём бота. Отсюда четыре следствия: **(а)** любое изменение
> фронтенда MAX может сломать мост в любой момент; **(б)** QR для входа привязывает
> устройство к твоему аккаунту — обращайся с ним как с паролем; **(в)** мост пересылает в
> Telegram и хранит в локальной базе сообщения всех, с кем ты переписываешься, а они на
> это не соглашались; **(г)** автоматизация веб-клиента MAX может нарушать его ToS и
> привести к блокировке аккаунта. Проект не аффилирован с MAX, VK или Telegram и никак
> ими не одобрен. Подробнее — [Дисклеймер](#дисклеймер).

## Как это работает

```
┌─────────────────┐         ┌──────────────────┐         ┌─────────────────┐
│   Max Messenger │◄────────│   max-in-tg      │────────►│    Telegram     │
│   (Web Client)  │ Puppeteer│   Bridge Server  │ Bot API │  (Topics Group) │
└─────────────────┘         └──────────────────┘         └─────────────────┘
                                     │
                                     ▼
                              ┌─────────────┐
                              │   SQLite DB  │
                              └─────────────┘
```

## Пользовательский опыт

Основной интерфейс — приватная Telegram-группа с включёнными Topics:

```
MAX Relay
├── Иван Петров        ← личный чат
├── Рабочий чат        ← группа
└── Мария              ← новый контакт (авто-создание)
```

> Каждый topic = один Max-чат. Пишешь в topic — сообщение уходит в Max. Получаешь из Max — приходит в нужный topic.

## Архитектура

### Telegram → Max

```
1. Сообщение в Telegram topic
2. Bridge: telegram_thread_id → max_chat_id (SQLite)
3. Browser lock (AsyncLock)
4. Puppeteer открывает нужный Max-чат
5. Верификация активного чата по заголовку
6. Отправка сообщения в Max
7. Запись результата в SQLite (delivery state)
```

### Max → Telegram

```
1. Polling: Puppeteer читает список Max-чатов
2. Приоритет: непрочитанные чаты
3. Извлечение новых сообщений
4. Если нет topic → авто-создание (или fail closed)
5. Отправка в Telegram topic
6. Дедупликация через SQLite message IDs
```

### Безопасность маршрутизации

- **Fail closed**: если topic создать нельзя — сообщение НЕ отправляется в общий чат
- **Верификация**: перед отправкой в Max проверяется заголовок активного чата
- **Browser lock**: polling и отправка не могут работать одновременно
- **Owner only**: доступ ограничен владельцем — тем, кто прошёл `/pair` (или задан в `TELEGRAM_OWNER_ID`)

## Быстрый старт

> Настройка идёт из Telegram: ни user id, ни id группы искать не нужно, на сервер
> заходить после установки тоже не нужно. Единственное, что ты вводишь руками, —
> токен бота.

### Требования

- **Во что это обходится:** постоянно включённый Linux-VPS с 2 ГБ RAM и ~10 ГБ диска
  (обычно 5–10 € в месяц). Ноутбук, который засыпает, не подойдёт. Cron-задача для
  перезапуска больше не нужна: мост сам перезапускает Chromium, когда тот разрастается
  (см. «Известные ограничения» и [SETUP_GUIDE §11.1](docs/SETUP_GUIDE.md))
- VPS с Debian 12/13 (или любой Linux с Docker)
- Docker + Docker Compose v2
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)
- Max аккаунт + телефон с приложением MAX (вход по QR)
- Приватная Telegram-группа с Topics — по желанию, определяется автоматически

### Поддерживаемые системы

Проект полностью работает в Docker (`node:22-bookworm-slim` внутри контейнера — Chromium, Xvfb, ffmpeg и все библиотеки уже установлены в образе), поэтому хостовая ОС практически не влияет на работу бота.

| Требование | Статус |
|---|---|
| Docker Engine + Docker Compose v2 | **Единственное обязательное требование** |
| Debian (Bookworm), x86_64/amd64 | Протестировано в production |
| Ubuntu и другие Linux-дистрибутивы с Docker | Должны работать так же (хост-агностично, образ внутри всегда Debian Bookworm) |
| arm64 (CPU) | Должно работать (базовый образ и `chromium` доступны для arm64), но пока не проверено на практике |
| RAM | **Минимум 2 ГБ** (`mem_limit: 2048m`, `shm_size: 1gb`). На 1 ГБ сборка падает с `Killed` / `exit code: 137`: в контейнере компилируется better-sqlite3 и работает Chromium |
| Диск | Минимум ~10 ГБ свободных под образ и данные |
| Windows / macOS | Подходят для разработки/тестов через Docker Desktop; для продакшена рекомендуется Linux-сервер |
| Без Docker (нативная установка) | Технически возможна на Debian/Ubuntu (Node 22, Chromium, Xvfb, ffmpeg), но это неофициальный путь — поддерживается только через Docker |

### 1. Установка

```bash
git clone https://github.com/GoPro3400/max-in-tg.git
cd max-in-tg
sh scripts/install.sh
```

Установщик спросит токен бота (создай бота в [@BotFather](https://t.me/BotFather) через
`/newbot`) — это единственное значение, которое нужно ввести. Дальше он всё сделает сам:
проверит Docker, запишет `.env`, соберёт образ и поднимет контейнер. Код привязки из
следующего шага мост печатает в логи. Всё остальное он выясняет сам и запоминает в базе.

### 2. Привязать бота к себе — `/pair`

Готовую строку `Send exactly:   /pair <код>` печатает сам установщик в конце вывода —
проще всего скопировать её оттуда. Тот же код лежит в логах контейнера, в поле
`pairingCode` (логи в production — это JSON, поэтому именно поле, а не текст сообщения):

```bash
docker compose logs --no-color | grep -o '"pairingCode":"[^"]*"' | tail -n 1
```

Команду выполняй из каталога проекта. Код повторяется в логах каждую минуту и меняется
при перезапуске контейнера — действует только последний.

Открой личный чат со своим ботом, нажми **Start** (на него бот намеренно не отвечает:
до привязки он не выполняет ничего, кроме `/pair`) и отправь код:

```
/pair k3Jq7Rr2_bA
```

Пока владелец не назначен, бот не выполняет никаких других команд и ни от кого —
единственное, что проходит, это `/pair` в личном чате. Незанятый бот принимает `/pair`
от кого угодно, а @username бота ищется поиском Telegram, поэтому код случайный и
длинный (8 случайных байт в base64url, вида `k3Jq7Rr2_bA`): подобрать его нельзя, а
выигрышем от подбора был бы тот самый QR для входа в MAX. После 5 неверных попыток этот
Telegram-аккаунт не может пробовать `/pair` 10 минут; сам код не меняется, поэтому чужой
перебор не мешает тебе привязаться. После привязки твой user id сохраняется в базе, и при
перезапуске код больше не запрашивается.

Если бот молчит и на `/pair`, мост уже привязан к другому Telegram-аккаунту (чужие
сообщения он игнорирует полностью). Узнай свой id у @userinfobot, впиши
`TELEGRAM_OWNER_ID=…` в `.env` и выполни `docker compose up -d --force-recreate`
(именно recreate: `restart` не перечитывает `.env`).

### 3. Войти в MAX по QR — прямо в Telegram

Дальше бот открывает web.max.ru в Chromium на сервере и, если сессии нет, присылает
QR-код тебе в личку. Сканировать надо камерой телефона из приложения MAX, поэтому
держи Telegram открытым на компьютере — один телефон сам себя не отсканирует.
На телефоне: **MAX → Настройки → Устройства → Подключить устройство** → отсканируй код.

- **QR приходит не мгновенно — 1–3 минуты.** Мост несколько раз подряд (до 45 секунд)
  перепроверяет, что на экране действительно форма входа, и только потом снимает код.
  Сначала приходит текст «🔐 Нужен вход в MAX», затем картинка.
- Код живёт около 2 минут. Сам MAX его **не** обновляет: он гасит код и ждёт нажатия
  «обновить» — бот нажимает за тебя и заменяет картинку в том же сообщении.
  Так что сканируй последнюю версию; если открыл чат давно — обнови сообщение.
- Как только вход выполнен, сообщение с QR удаляется, приходит «✅ MAX подключён»,
  и мост стартует.
- Ожидание не ограничено по времени: бот держит QR свежим и не чаще раза в 30 минут
  напоминает, что всё ещё ждёт входа. Если сообщение с QR удалили — отправь `/login`,
  бот пришлёт новую картинку отдельным сообщением.
- Сообщение, отправленное в Telegram до подключения MAX, не пропадает молча: бот ответит
  «⏳ MAX ещё не подключён — сообщение НЕ отправлено».

> :warning: QR — это доступ к твоему аккаунту MAX: кто отсканирует, тот и подключит
> своё устройство. Поэтому он уходит **только в личный чат владельца**, никогда в
> группу, и удаляется сразу после входа. Никому его не пересылай.

### 4. Группа с Topics (рекомендуется)

1. Создай приватную группу и включи в ней **Topics** (Темы) — **до** добавления бота:
   включение Тем меняет внутренний id группы, а автоопределение срабатывает ровно один
   раз, в момент добавления бота или изменения его прав
2. Добавь бота и сделай его админом. На экране назначения админа нужно ровно одно право:
   **Manage Topics** (без него темы не создаются и из MAX ничего не доставляется);
   **Pin Messages** желательно — без него не закрепится intro-карточка. Переключателей
   «Send Messages» / «Send Media» на этом экране нет, и они не нужны: админ группы и так
   может писать и слать медиа
3. Больше ничего делать не нужно — бот сам подхватит группу и напишет в неё
   «✅ Эта группа подключена»

Порядок не важен, но отвечает бот в разные места: если он попал в группу **до** `/pair`,
в самой группе он молчит (владельца ещё нет), а результат приходит ответом на `/pair` в
личном чате — там же и претензии «Кстати: … не включены Темы».

Если Topics не включены или нет прав админа, бот напишет, что именно поправить; выдал
права позже — удали бота из группы и добавь заново, Telegram не повторяет это событие.
Если автоопределение выбрало не ту группу, отправь `/relay` в нужной — мост переедет
туда (уже созданные темы останутся в старой). Без группы мост работает и так, но
наполовину: чаты MAX приходят в личный чат одним потоком, а **всё написанное боту в
личку уходит в один выбранный чат MAX** (`/chats`, `/select <номер>`, текущий виден в
`/status` как `Fallback selected:`).

### 5. Проверка

В Telegram: `/status` (состояние моста), `/chats` (какие чаты MAX видны),
`/check` (селекторы Max Web).

Сразу после настройки группа будет пустой — так и задумано: при первом запуске вся
существующая переписка MAX помечается прочитанной, а темы создаются по мере прихода
новых сообщений. `/sync` создаст темы для всех текущих чатов.

## Telegram команды

| Команда | Описание |
|---------|----------|
| `/pair <код>` | Первый запуск: назначить себя владельцем моста. Только в личном чате и только пока владелец не назначен; код печатается в логах контейнера |
| `/login` | Прислать QR для входа в MAX (если сессия отвалилась или сообщение с QR удалили). QR приходит в личный чат |
| `/relay` | Отправить внутри приватной супергруппы с Topics, где бот админ, — эта группа станет релеем. Работает и когда релей уже выбран (только от владельца), так что это же способ переехать в другую группу |
| `/select <номер>` | Только когда группа-релей не подключена: выбрать, в какой чат MAX уходят сообщения из личного чата (номер из `/chats`) |
| `/status` | Состояние bridge (чаты, маршруты, ошибки polling) |
| `/check` | Проверка Max Web селекторов |
| `/diagnostics` | Отправить diagnostic-файлы |
| `/sync` | Принудительное обновление topics |
| `/chats` | Список маршрутов Max → Telegram |
| `/history` | Последние сообщения в текущем topic |
| `/deliveries` | Статистика доставки (sent/failed/pending) |
| `/merge <name>` | Объединить дублированный чат в текущий topic |
| `/unmerge <name>` | Отменить объединение |
| `/mute <name>` | Не пересылать чат (например, рекламную ленту MAX «Интересное для вас») |
| `/unmute <name>` | Вернуть пересылку; накопленный за время тишины бэклог не досылается |

## Известные ограничения

| Ограничение | Описание |
|-------------|----------|
| Max Web DOM | Селекторы зависят от DOM Max Web и могут сломаться при обновлении |
| Память Chromium | Утечка, из-за которой рендерер за ~3 часа вырастал до ~2 ГБ, устранена. Для страховки мост между циклами опроса перезагружает вкладку MAX при 900 МБ и перезапускает Chromium при 1300 МБ или раз в 6 часов (`MAX_PAGE_RELOAD_MEMORY_MB`, `MAX_BROWSER_MEMORY_LIMIT_MB`, `MAX_BROWSER_RECYCLE_MINUTES`); Telegram-бот при этом не отключается, cron не нужен — [SETUP_GUIDE §11.1](docs/SETUP_GUIDE.md) |
| Стикеры | Захват из сети (Lottie/asset), иначе кадр с canvas; если не вышло ни то, ни другое — уходит текстом `[Стикер]` |
| Реакции | Бот в Telegram может поставить только одну реакцию из списка Telegram — видна самая частая (или ближайшая замена). Реакции работают на сообщениях, которые видны в MAX Web; разметка реакций взята из кода MAX Web, при её изменении — `/diagnostics` и `MAX_SELECTORS_*` реакций |
| At-least-once delivery | Возможны дубли при падении между send и SQLite write |
| Идентификация чатов | Сейчас по title/index, одноимённые чаты могут путаться |
| Один пользователь | Рассчитано на self-hosted для одного Max-аккаунта |
| Точность матчинга медиа-ответов | Сопоставление best-effort: фото матчатся по dHash (наиболее надёжно), остальные типы — только при наличии CDN-токена оригинала; старые сообщения (до обновления) не матчатся задним числом; при неуверенности цитата не ставится |
| Telegram→MAX replies | Работает для ответов на текстовые и медиа-оригиналы из MAX, а также на свои же ранее отправленные из Telegram текстовые сообщения; ответы на свои же не текстовые сообщения (фото и т.д.) не резолвятся. Всегда best-effort: если бот не смог найти нужный пузырь в MAX Web, сообщение уходит без цитаты, а не с ошибкой |

## Безопасность

- `.env` и Chrome profile **никогда** не коммитятся
- Telegram доступ ограничен владельцем (`/pair` или `TELEGRAM_OWNER_ID`) и группой-релеем
- До привязки владельца бот принимает ровно одну команду — `/pair <код>` в личном чате
- QR для входа в MAX отправляется **только** в личный чат владельца (никогда в группу)
  и удаляется сразу после успешного входа
- Пока на экране висит форма входа MAX, диагностика **не делает скриншот**, а содержимое
  `<svg>` вырезается из всех HTML-дампов (даже при `DIAGNOSTIC_REDACT_TEXT=false`): MAX
  рисует QR инлайновым SVG, а `/diagnostics` выгружает дампы в тот чат, откуда его позвали
- Всё остальное в диагностическом снимке **не** анонимизируется: вне экрана входа
  скриншот показывает окно MAX как есть, вместе с открытым в этот момент чатом, а
  `/diagnostics` выгружает его в тот чат, откуда команду позвали, — включая группу-релей.
  `DIAGNOSTIC_REDACT_TEXT=true` редактирует **только HTML-дампы**. Зови `/diagnostics` из
  личного чата и удаляй файлы, когда закончил
- Контейнер работает под non-root uid 10001 в обеих конфигурациях; `docker-compose.yml`
  (его поднимает установщик) ограничивает память и ротирует логи, а hardened-конфиг
  `docker-compose.prod.yml` добавляет `no-new-privileges`, `cap_drop: ALL`, read-only
  root fs и `pids_limit` — запускается отдельно: `docker compose -f docker-compose.prod.yml up -d --build`
- Chrome profile = активная Max-сессия (хранить как пароль)
