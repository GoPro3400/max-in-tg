> **Прочитай это первым.** Это неофициальная автоматизация: публичного API у MAX нет,
> поэтому мост открывает настоящий веб-клиент web.max.ru в настоящем Chromium **на твоём
> сервере**, под **твоим** аккаунтом MAX, со stealth-плагином, задача которого — не дать
> веб-клиенту распознать в нём бота. Отсюда четыре следствия: **(а)** любое изменение
> фронтенда MAX может сломать мост в любой момент; **(б)** QR для входа привязывает
> устройство к твоему аккаунту — обращайся с ним как с паролем; **(в)** мост пересылает в
> Telegram и хранит в локальной базе сообщения всех, с кем ты переписываешься, а они на
> это не соглашались; **(г)** автоматизация веб-клиента MAX может нарушать его ToS и
> привести к блокировке аккаунта. Проект не аффилирован с MAX, VK или Telegram и никак
> ими не одобрен. Подробнее — [Дисклеймер](#дисклеймер).

## Как Это Выглядит Для Пользователя

Основной интерфейс — приватная Telegram-группа с включёнными Topics:

```
MAX Relay
├── Иван Петров        ← личный чат
├── Работа             ← рабочий чат
├── Семья              ← семейная группа
└── Мария              ← новый контакт (авто-создание)
```

**Как пользоваться:**

1. Открываешь topic с именем контакта
2. Пишешь текст, отправляешь фото/голосовое/видео/документ
3. Сообщение уходит в соответствующий Max-чат
4. Входящие из Max приходят в тот же topic

> Никаких команд для ежедневной переписки не нужно. Команды `/status`, `/check` и т.д. — только для обслуживания.

## Что Уже Реализовано

### Типы сообщений

| Тип | Max → Telegram | Telegram → Max | Примечание |
|-----|:--------------:|:--------------:|-----------|
| Текст | :white_check_mark: | :white_check_mark: | |
| Ответы (reply) | :warning: | :warning: | MAX→TG: ответы на текст и на медиа приходят цитатой оригинала (медиа — по перцептивному хэшу изображения и/или CDN-токену, best-effort). TG→MAX: ответ на пересланный из MAX **текстовый или медиа** оригинал уходит в MAX настоящим reply — бот находит нужный пузырь в MAX Web (по автору/времени/тексту, либо по CDN-токену для медиа) и жмёт «Ответить». Ответ на своё же ранее отправленное из Telegram **текстовое** сообщение тоже работает — по отпечатку, сохранённому сразу после отправки этого сообщения в MAX. Всё это best-effort — если оригинал не найден или UI не среагировал, сообщение всё равно уходит, но без цитаты. Ответы на свои же не текстовые сообщения (фото и т.д.) пока не резолвятся. |
| Фото / файлы | :white_check_mark: | :white_check_mark: | TG→MAX через меню вложений MAX («Photo or video» / «File») + проверка доставки. [Подробнее](docs/MEDIA_PIPELINE.md) |
| Голосовые | :white_check_mark: | :warning: | MAX→TG: настоящее голосовое (клик play → network intercept → .ogg/.opus/.mp3). TG→MAX: уходит через меню «File», поэтому в MAX появляется прикреплённым аудиофайлом, а не голосовым пузырём |
| Видео-кружки | :white_check_mark: | :warning: | MAX→TG: настоящий video note (обнаружение roundVideo/videoCanvas). TG→MAX: уходит через «Photo or video» и приходит обычным встроенным видео, не кружком |
| Документы | :white_check_mark: | :white_check_mark: | PDF, DOCX, ZIP и другие файлы |
| Анимированные стикеры | :white_check_mark: | — | Lottie → `.tgs` (gzip-Lottie); фолбэк — кадры canvas → `.gif`/`.webm`. [Подробнее](docs/MEDIA_PIPELINE.md) |

> :bulb: Медиа и стикеры: как устроена отправка фото/файлов через меню вложений MAX
> и превращение Lottie-стикеров в `.tgs`/`.gif`/`.webm` — в [docs/MEDIA_PIPELINE.md](docs/MEDIA_PIPELINE.md).

### Инфраструктура

| Функция | Описание |
|---------|----------|
| **Telegram Topics** | Авто-создание topics для новых Max-чатов |
| **Intro-карточки** | Закреплённое сообщение с именем и ID чата в каждом topic |
| **Delivery state** | Таблица `message_deliveries` (pending/sent/failed) |
| **Session validation** | Проверка URL Max Web + авто-рестарт при expired session |
| **Browser lock** | `AsyncLock` — polling и отправка не переключают чат одновременно |
| **Active chat verify** | Проверка заголовка перед отправкой — защита от отправки не тому |
| **Startup priming** | На первом запуске вся существующая история Max помечается прочитанной и не пересылается в Telegram; на последующих запусках прайминг не делается, поэтому сообщения, пришедшие пока мост лежал, всё-таки доставляются |
| **Diagnostics** | Screenshot + HTML снимки в `logs/diagnostics` |
| **Media conversion** | ffmpeg-static + fluent-ffmpeg + sharp |
| **`/merge` / `/unmerge`** | Объединение дублированных чатов в один topic |
| **Настройка из Telegram** | `/pair` вместо поиска user id, вход в MAX по QR прямо в чате с ботом, группа-релей определяется автоматически при добавлении бота |
| **Docker** | `docker-compose.yml` (его поднимает установщик: лимит памяти, ротация логов) и hardened `docker-compose.prod.yml`; в образе есть HEALTHCHECK — `docker compose ps` показывает `Up (healthy)` |
| **Тесты** | Unit- и интеграционные тесты (vitest): messages, asyncLock, fileHelpers, networkCapture, config, database, mediaService, онбординг и все пути доставки над реальной in-memory SQLite |
| **Shared utilities** | `fileHelpers.js` и `networkCapture.js` — общие утилиты |

## Как Работает Архитектура

### Общая схема

```
┌─────────────────┐         ┌──────────────────────────────┐         ┌─────────────────┐
│   Max Messenger │◄────────│       max-in-tg Bridge       │────────►│    Telegram     │
│   (Web Client)  │ Puppeteer│                              │ Bot API │  (Topics Group) │
└─────────────────┘         │  ┌────────┐  ┌───────────┐  │         └─────────────────┘
                            │  │ SQLite │  │ AsyncLock │  │
                            │  └────────┘  └───────────┘  │
                            └──────────────────────────────┘
```

### Telegram → Max (отправка)

```
1. Пользователь пишет в Telegram topic
2. Bridge находит: telegram_chat_id + telegram_thread_id → max_chat_id
3. Max Web client получает browser lock
4. Puppeteer открывает нужный Max-чат
5. Система проверяет заголовок активного чата
6. Если проверка OK → сообщение отправляется в Max
7. delivery_state: pending → sent (или failed)
```

### Max → Telegram (приём)

```
1. Puppeteer каждые ~650ms читает список Max-чатов
2. Непрочитанные чаты получают приоритет
3. Система считывает новые сообщения (по MAX_CHATS_PER_POLL=4 за цикл)
4. Если для Max-чата нет topic → bridge создаёт topic
5. Если создать topic нельзя → fail closed (НЕ отправляет в общий чат)
6. Сообщение отправляется в Telegram topic
7. SQLite хранит ID обработанных сообщений (дедупликация)
```

### Таблицы БД

| Таблица | Назначение |
|---------|-----------|
| `chats` | Список Max-чатов |
| `chat_mappings` | Связка Max chat ID ↔ Telegram topic ID |
| `messages` | Все пересланные сообщения (обе стороны) |
| `message_deliveries` | Статус доставки (pending/sent/failed) |
| `settings` | Ключ-значение настройки |

## Быстрый Старт На VPS

> Вся настройка идёт из Telegram: user id и id группы искать не нужно, заходить на
> сервер после установки — тоже. Руками вводится только токен бота.

### Требования

- **Во что это обходится**: постоянно включённый Linux-VPS с 2 ГБ RAM и ~10 ГБ диска
  (обычно 5–10 € в месяц). Ноутбук, который засыпает, не подойдёт. Cron-задача для
  перезапуска больше не нужна: мост сам перезапускает Chromium, когда тот разрастается
  (см. [Известные ограничения](#известные-ограничения) и SETUP_GUIDE §11.1)
- **Сервер**: Debian 12/13 VPS с Docker + Docker Compose v2
- **Telegram**: токен бота от [@BotFather](https://t.me/BotFather); приватная группа
  с Topics — по желанию, определяется автоматически
- **Max**: аккаунт на web.max.ru + телефон с приложением MAX (вход по QR)

### Поддерживаемые системы

Бот целиком работает в Docker: образ собирается на `node:20-bookworm-slim`, и Chromium, Xvfb, ffmpeg и все нужные библиотеки устанавливаются внутри контейнера. Хостовая ОС изолирована от рантайма Docker'ом, поэтому почти не имеет значения.

| Требование | Статус |
|---|---|
| Docker Engine + Docker Compose v2 | **Единственное реальное требование** — всё, что умеет их запускать, подходит |
| Debian (Bookworm), x86_64/amd64 | Протестировано в production |
| Ubuntu | Должна работать так же (Debian-based, наибольшая уверенность), хост-ОС не влияет — контейнер всегда Debian Bookworm |
| Другие Linux-дистрибутивы с Docker (Fedora и т.д.) | Должны работать так же |
| CPU arm64 | Должно работать (базовый образ и пакет `chromium` есть под arm64), но пока **не проверено** на практике |
| RAM | **Минимум 2 ГБ** (`mem_limit: 2048m`, `shm_size: 1gb`). На 1 ГБ сборка падает с `Killed` / `exit code: 137`: в контейнере компилируется better-sqlite3 и работает Chromium |
| Диск | Минимум ~10 ГБ свободных под образ и данные |
| Windows / macOS | Подходят для разработки и тестов через Docker Desktop; для прода рекомендован Linux-сервер (аптайм, ресурсы) |
| Нативная установка без Docker | Возможна на Debian/Ubuntu (нужны Node 20, Chromium, Xvfb, ffmpeg), но это неофициальный путь — не поддерживается как основной сценарий |

### Шаг 1: Установка

```bash
git clone https://github.com/GoPro3400/max-in-tg.git
cd max-in-tg
sh scripts/install.sh
```

Установщик спросит токен бота — создай бота в [@BotFather](https://t.me/BotFather)
командой `/newbot` и вставь выданный токен. Это единственное значение, которое нужно
ввести руками: user id владельца и id группы мост определяет сам и запоминает в своей
базе (таблица `settings`), так что после перезапуска настройка не повторяется.

Остальное установщик делает сам: проверяет Docker и Compose v2, создаёт `.env` (токен
не печатается обратно в терминал), готовит каталоги `data/ tmp/ logs/`, собирает образ и
поднимает контейнер. Код привязки из следующего шага мост печатает в логи. Повторный
запуск безопасен — существующий `.env` не перезаписывается.

### Шаг 2: Привязка владельца — `/pair`

Готовую строку `Send exactly:   /pair <код>` печатает сам установщик в конце вывода —
проще всего скопировать её оттуда.

Открой личный чат со своим ботом, нажми **Start** (на него бот намеренно не отвечает: до
привязки он не выполняет ничего, кроме `/pair`) и отправь код:

```
/pair k3Jq7Rr2_bA
```

Бот ответит «✅ Готово, ты владелец этого моста». Пока владелец не назначен, бот не
выполняет вообще никаких других команд и ни от кого — единственное, что проходит, это
`/pair` в личном чате. Неверный код логируется как отклонённая попытка, а после пяти
таких попыток код перевыпускается: новый печатается в ту же строку логов, так что
подбор всегда начинается с нуля, а тебе достаточно взять свежий код.

Почему код длинный и случайный (8 случайных байт в base64url, вида `k3Jq7Rr2_bA`):
непривязанный бот принимает `/pair` от кого угодно, а его @username виден в поиске
Telegram — короткий числовой код можно было бы перебрать, и выигрышем стал бы QR-код
для входа в твой аккаунт MAX.

Если код потерялся — достань последний из логов (в production логи пишутся в JSON, код
лежит в поле `pairingCode`, а не в тексте сообщения; команда — из каталога проекта):

```bash
docker compose logs --no-color | grep -o '"pairingCode":"[^"]*"' | tail -n 1
```

Если бот молчит и на `/pair`, мост уже привязан к другому Telegram-аккаунту (чужие
сообщения он игнорирует полностью). Узнай свой id у @userinfobot, впиши
`TELEGRAM_OWNER_ID=…` в `.env` и выполни `docker compose up -d --force-recreate`
(именно recreate: `restart` не перечитывает `.env`).

### Шаг 3: Вход в MAX по QR-коду

После привязки мост открывает web.max.ru в Chromium на сервере. Если активной сессии
нет, бот присылает QR-код тебе в личку. Сканировать надо камерой телефона из приложения
MAX, поэтому держи Telegram открытым на компьютере — один телефон сам себя не
отсканирует. На телефоне:
**MAX → Настройки → Устройства → Подключить устройство** → отсканируй код.

- **QR приходит не мгновенно — 1–3 минуты.** Мост несколько раз подряд (до 45 секунд)
  перепроверяет, что на экране действительно форма входа, и только потом снимает код:
  сначала приходит текст «🔐 Нужен вход в MAX», затем картинка.
- Код живёт около 2 минут. Сам MAX его **не** перевыпускает: он гасит код (размывает
  и показывает «QR-код истёк») и ждёт нажатия «обновить». Бот нажимает за тебя и
  заменяет картинку в том же сообщении, чат не засоряется мёртвыми кодами.
- Как только вход выполнен, сообщение с QR удаляется, приходит «✅ MAX подключён»,
  и мост запускается.
- Ожидание не ограничено по времени: пока входа нет, мосту всё равно нечего делать,
  поэтому он держит QR свежим сколько угодно и не чаще раза в 30 минут напоминает, что
  всё ещё ждёт. Если сообщение с QR удалили — отправь `/login`, бот пришлёт новую
  картинку отдельным сообщением.
- Сообщение, отправленное в Telegram, пока MAX не подключён, не теряется молча: бот
  ответит «⏳ MAX ещё не подключён — сообщение НЕ отправлено» — отправь его снова после
  «✅ MAX подключён».
- Та же схема работает и потом: если MAX выкинет сессию, бот сам пришлёт новый QR
  вместо бесконечных перезапусков браузера.

> :warning: **QR — это учётные данные.** Кто его отсканирует, тот подключит своё
> устройство к твоему аккаунту MAX. Поэтому код уходит **только в личный чат
> владельца** — никогда в группу-релей, у которой могут быть другие участники, — и
> удаляется сразу после входа. Никому не пересылай.

### Шаг 4: Группа с Topics (рекомендуется)

1. Создай приватную группу и включи **Topics** (Темы) — **до** добавления бота:
   включение Тем меняет внутренний id группы, а автоопределение срабатывает ровно один
   раз, в момент добавления бота или изменения его прав
2. Добавь бота в группу и выдай ему права администратора. На экране назначения админа
   нужно ровно одно право:
   - :white_check_mark: **Manage Topics** — обязательно: без него темы не создаются и из
     MAX вообще ничего не доставляется
   - :white_check_mark: **Pin Messages** — желательно: без него не закрепится
     intro-карточка, мост продолжит работать
   - Переключателей **Send Messages** / **Send Media** на этом экране нет, и они не
     нужны: администратор группы и так может писать и слать медиа
3. Больше ничего вводить не нужно: бот подхватит группу сам и напишет в неё
   «✅ Эта группа подключена»

Порядок шагов 2 и 4 не важен, но отвечает бот в разные места. Если бота добавили в группу
ещё до `/pair`, группа запоминается и подключается сразу после привязки — но только после
того, как бот убедится, что новый владелец действительно состоит в этой группе (иначе кто
угодно мог бы заранее подсунуть свою группу и получать туда твою переписку); в самой
группе он при этом молчит, а результат и претензии приходят ответом на `/pair` в личном
чате.

Если Topics в группе не включены или бот не админ — он объяснит, что поправить, и группу
не подключит; выдал права позже — удали бота из группы и добавь заново, Telegram не
повторяет это событие. Если автоопределение выбрало не ту группу, отправь `/relay` в
нужной — мост переедет туда, а уже созданные темы останутся в старой группе. Без группы
мост работает и так, но наполовину: чаты MAX приходят в личный чат одним потоком, а
**всё написанное боту в личку уходит в один выбранный чат MAX** независимо от того, на
какое сообщение ты отвечаешь (`/chats`, `/select <номер>`, текущий получатель виден в
`/status` как `Fallback selected:`).

### Шаг 5: Проверка

В Telegram: `/status` — состояние моста, `/chats` — какие чаты MAX видны и куда
маршрутизируются, `/check` — живы ли селекторы Max Web.

Сразу после настройки группа будет пустой — так и задумано: при первом запуске вся
существующая переписка MAX помечается прочитанной, а темы создаются по мере прихода
новых сообщений. `/sync` создаст темы для всех текущих чатов.

> Полная инструкция для новичков: **[docs/SETUP_GUIDE.md](docs/SETUP_GUIDE.md)**

## Telegram Команды

| Команда | Описание |
|---------|----------|
| `/pair <код>` | Первый запуск: назначить себя владельцем моста. Работает только в личном чате и только пока владелец не назначен; код печатается в логах контейнера |
| `/login` | Прислать QR для входа в MAX — если сессия отвалилась или сообщение с QR удалили. QR приходит в личный чат владельца |
| `/relay` | Отправить в приватной супергруппе с включёнными Темами, где бот администратор, — эта группа станет релеем. Работает и когда релей уже выбран (только от владельца), так что это же способ переехать в другую группу |
| `/status` | Состояние bridge (чаты, маршруты, poll failures) |
| `/check` | Проверка ключевых Max Web селекторов |
| `/diagnostics` | Отправить последние diagnostic-файлы |
| `/sync` | Принудительно обновить чаты и topics |
| `/chats` | Список Max-чатов и маршрутов |
| `/history` | Последние сообщения в текущем topic |
| `/deliveries` | Статистика доставки (sent/failed/pending) |
| `/merge <name>` | Объединить дублированный чат в текущий topic |
| `/unmerge <name>` | Отменить объединение |
| `/mute <name>` | Не пересылать чат (рекламные ленты MAX) |
| `/unmute <name>` | Вернуть пересылку без вываливания бэклога |
| `/select <N>` | Только когда группа-релей не подключена: выбрать, в какой чат MAX уходят сообщения из личного чата (номер из `/chats`) |

## Безопасность

### Что защищено

- `.env` не коммитится в Git
- `data/chrome-profile` не коммитится — это активная Max-сессия
- SQLite production DB не коммитится
- Telegram доступ ограничен владельцем (`/pair` или `TELEGRAM_OWNER_ID`) и группой-релеем
- До привязки владельца бот принимает ровно одну команду — `/pair <код>` в личном чате,
  так что незанятого бота нельзя увести
- QR для входа в MAX отправляется **только** в личный чат владельца (никогда в
  группу-релей) и удаляется сразу после успешного входа
- Пока на экране открыта форма входа MAX, диагностика **не делает скриншот**, а
  содержимое `<svg>` вырезается из каждого HTML-дампа — даже при
  `DIAGNOSTIC_REDACT_TEXT=false`. MAX рисует QR инлайновым SVG, а `/diagnostics`
  выгружает дампы в тот чат, из которого его вызвали, в том числе в группу-релей
- Всё остальное в диагностическом снимке **не** анонимизируется: вне экрана входа
  скриншот показывает окно MAX как есть, вместе с открытым в этот момент чатом, а
  `/diagnostics` выгружает его в тот чат, откуда команду позвали, — включая группу-релей.
  `DIAGNOSTIC_REDACT_TEXT=true` редактирует **только HTML-дампы**. Зови `/diagnostics` из
  личного чата и удаляй файлы, когда закончил
- Контейнер запускается от **non-root** пользователя (uid 10001) в обеих конфигурациях;
  `docker-compose.yml` (его поднимает установщик) ограничивает память и ротирует логи
- Hardened-конфиг `docker-compose.prod.yml` добавляет `no-new-privileges`,
  `cap_drop: ALL`, read-only root fs, `pids_limit` и tmpfs `/tmp`; запускается отдельно:
  `docker compose -f docker-compose.prod.yml up -d --build`

### Принципы маршрутизации

- Если topic создать нельзя → **fail closed** (не отправлять в общий чат)
- Перед отправкой обязательна верификация активного Max-чата
- Если верификация не прошла → сообщение **не отправляется**
- Browser lock исключает race condition при переключении чатов

## Известные Ограничения

| # | Ограничение | Подробности |
|---|-------------|-------------|
| 1 | **Max Web DOM** | Проект зависит от селекторов DOM. При обновлении Max Web — возможны поломки. Диагностика: `/check` |
| 2 | **Стикеры** | Захват из сети (Lottie/asset), иначе кадр с canvas; если не вышло ни то, ни другое — уходит текстом `[Стикер]` |
| 3 | **Утечка памяти Chromium** | Рендерер вырастает до ~2 ГБ примерно за 3 часа, после чего фото из Telegram перестают уходить в MAX. Мост сам перезапускает браузер между циклами опроса — раз в 2 часа или сразу, как Chromium превысит 1300 МБ (`MAX_BROWSER_RECYCLE_MINUTES`, `MAX_BROWSER_MEMORY_LIMIT_MB`); Telegram-бот при этом не отключается, cron не нужен — [SETUP_GUIDE §11.1](docs/SETUP_GUIDE.md) |
| 4 | **At-least-once** | Возможны дубли при падении между send и SQLite write |
| 5 | **Идентификация чатов** | По title/index — одноименные чаты могут путаться |
| 6 | **Один пользователь** | Self-hosted для одного Max-аккаунта |
| 7 | **Нет retry policy** | Failed deliveries не повторяются автоматически |
| 8 | **Точность матчинга медиа-ответов** | Best-effort: фото матчатся по dHash (наиболее надёжно), остальные типы — только при наличии CDN-токена оригинала; старые сообщения (до обновления) не матчатся задним числом; при неуверенности цитата не ставится |
| 9 | **Telegram→MAX replies** | Работает для ответов на текстовые и медиа-оригиналы из MAX, а также на свои же ранее отправленные из Telegram текстовые сообщения; ответы на свои же не текстовые сообщения (фото и т.д.) пока не резолвятся. Всегда best-effort: если бот не смог найти нужный пузырь в MAX Web, сообщение уходит без цитаты, а не с ошибкой |

Статус: личный проект одного человека. Поддержка — по возможности, обратная совместимость не гарантируется.

Проект предоставляется «как есть», без каких-либо гарантий (см. [LICENSE](LICENSE)).

Предназначен для личного и образовательного использования. Пользователь самостоятельно несёт ответственность за соблюдение условий использования (ToS) сервиса MAX и применимого законодательства своей юрисдикции. Автоматизация веб-клиента MAX может нарушать его ToS и привести к блокировке аккаунта.

Мост копирует переписку — в том числе сообщения, написанные не тобой, людьми, которые не соглашались на их пересылку в Telegram и хранение в локальной базе. В зависимости от юрисдикции это может накладывать обязательства по защите персональных данных. Не запускай мост на общих, рабочих или групповых аккаунтах без ведома участников переписки.

Проект не аффилирован с MAX, VK или Telegram и никак ими не одобрен.
