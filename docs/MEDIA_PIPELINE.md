# Медиа-конвейер: фото, файлы, стикеры, голос, видео

Этот документ описывает, как `max-in-tg` передаёт **медиа** между MAX и Telegram —
в первую очередь **отправку фото/файлов из Telegram в MAX** и **анимированные
стикеры из MAX в Telegram**, потому что обе вещи завязаны на нетривиальное
поведение веб-клиента MAX.

У MAX нет публичного API, поэтому бот управляет веб-клиентом
(`https://web.max.ru/`) через Puppeteer/Chromium. Любая отправка/чтение — это
эмуляция действий пользователя в DOM.

---

## 1. Отправка фото и файлов: Telegram → MAX

### Проблема

Наивный способ — найти `input[type="file"]` в композере и выставить файл
(через `fileChooser.accept()` или `elementHandle.uploadFile()`) — **не работает**.
MAX не вешает обработчик на этот скрытый `input` напрямую: установка `input.files`
ничего не прикрепляет, превью в композере не появляется. Раньше из-за этого бот
**рапортовал успех, но фото не доходило** до собеседника.

### Как на самом деле устроено прикрепление в MAX

Кнопка-скрепка в композере (`button[aria-label="Upload file"]`,
`aria-haspopup="dialog"`) открывает **actions-меню** с пунктами:

| Пункт меню | aria-label | Назначение |
|------------|-----------|------------|
| Photo or video | `Photo or&nbsp;video` | фото и видео (инлайн-картинкой) |
| File | `File` | любой файл как документ |
| Contact | `Contact` | контакт |

> ⚠️ В `aria-label` пункта «Photo or video» используется **неразрывный пробел**
> (`&nbsp;`, U+00A0), поэтому селектор по точному совпадению не сработает —
> используем подстроку: `[aria-label*="Photo"]`.

Реальный file-chooser открывается **только после клика по пункту меню**.

### Алгоритм `sendFile()` (`src/adapters/maxWebClient.js`)

1. `ensureActiveChat(chatId)` — открыть нужный чат.
2. Кликнуть скрепку `selectors.attachButton` → открывается меню.
3. Дождаться пункта меню и кликнуть его, **выбирая по расширению файла**:
   - изображения/видео (`jpg/png/gif/webp/mp4/webm/mov/...`) → `attachMenuMedia` («Photo or video»);
   - всё остальное → `attachMenuFile` («File»).
4. Клик по пункту запускает file-chooser → `fileChooser.accept([path])`.
5. Подождать, пока вложение «осядет» в композере (`attachPreview`, мягкая проверка).
6. Запомнить число исходящих пузырей, нажать «Send message».
7. **Проверить доставку** (см. ниже).

### Честная проверка доставки

`sendFile` (и `sendText` через `submitComposer`) после отправки **подтверждают**,
что сообщение реально ушло:

- `sendFile` — ждёт, что число элементов `selectors.outgoingBubble`
  (`[data-bubbles-variant="outgoing"]`) **увеличилось**;
- `sendText` — ждёт, что композер **очистился**.

Если подтверждения нет за ~10 c — метод **бросает ошибку**, мост помечает доставку
`failed` и шлёт пользователю `⚠️ Failed to send to MAX`. Это исключает «тихие
потери», когда бот считает сообщение отправленным, а собеседник его не получил.

## 2. Стикеры в обе стороны

Стикер должен выглядеть стикером: прозрачный, без «пузыря», без плашки GIF. Поэтому
в Telegram он уходит **настоящим стикером** (`sendSticker`), а старые форматы
остались только фолбэками.

### MAX → Telegram

```
MAX (Lottie JSON / картинка / canvas)
      │
      ├─ анимированный: Lottie пойман из сети (findNetworkLottie, «...lottie=true»)
      │     └─ рендер lottie-web в отдельной вкладке → PNG-кадры
      │  или кадры <canvas> самого пузыря (если Lottie не пойман)
      │        └─ framesDirToWebmSticker: VP9 .webm с альфой, ≤3 c, ≤30 fps,
      │           ≤256 КБ, 512 px  ──►  sendSticker (видео-стикер)
      │
      ├─ статичный: картинка стикера ──► toWebpSticker (WEBP 512 px) ──► sendSticker
      │
      └─ фолбэки: Telegram не принял стикер → анимированный GIF (sendAnimation)
                  или первый кадр/картинка фотографией; в крайнем случае — «[Стикер]»
```

- Сетевые Lottie-захваты используются, только когда новый стикер **один**: при двух
  сразу они не привязываются к пузырям, и анимации менялись местами. Иначе каждый
  стикер снимается со своего `<canvas>`.
- «Отпечаток» анимированного стикера для защиты от повторной пересылки — первый
  кадр (`frame-000.png`), так что он не зависит от того, какой кодер сработал.

### Telegram → MAX

| Стикер Telegram | Что получает MAX |
|-----------------|------------------|
| статичный `.webp` | PNG с прозрачностью |
| анимированный `.tgs` (Lottie) | рендер в браузере MAX (lottie-web) → анимированный GIF с прозрачностью |
| видео-стикер `.webm` | анимированный GIF с прозрачностью |
| не удалось сконвертировать | эмодзи стикера текстом (или `[стикер]`) |

## 3. Остальные типы медиа (кратко)

| Тип | MAX → TG | TG → MAX |
|-----|----------|----------|
| Фото | `sendPhoto` | меню «Photo or video» (см. §1) |
| Голос | активный клик play → перехват аудио из сети → `.ogg`/`.opus`/`.mp3` → `sendVoice` | меню «File» |
| Видео-кружок | детект `videoMessage/videoCanvas` → `sendVideoNote` | меню «Photo or video» |
| Видео | перехват из сети → `sendVideo` | меню «Photo or video» |
| Документ | клик по карточке файла → перехват из сети или папка загрузок браузера → `sendDocument` | меню «File» |

**Файлы MAX → Telegram.** В MAX файл — карточка `.attaches > button.container`: имя в
`.title`, размер в `.info` («Скачать • 1.23 MB»), ссылки на файл в странице нет — по
клику MAX сам запрашивает адрес и скачивает. Мост кликает по карточке **именно этого**
пузыря (раньше пузыри файлов/голосовых считались в странице и в Node по-разному, и после
своего исходящего файла скачивался не тот). Загрузку ждёт, пока файл растёт (до 2 минут),
а не 5 секунд. Файл больше 50 МБ (предел Telegram для ботов) не скачивается вовсе —
в Telegram уходит «📎 «имя» (1,5 ГБ) — больше 50 МБ…»; удалённый в MAX — «файл удалён
или недоступен»; не скачавшийся файл, голосовое или кружок пробуется ещё на двух
следующих чтениях и только потом заменяется уведомлением (раньше сразу уходил текст
`[Document]`). Картинка-превью файла (фото или видео, отправленные файлом) — не фото:
пересылается сам файл. Ссылки в тексте («…/file/…») и карточка превью ссылки (`.share`)
файлами и фото не считаются. Геопозиция, опрос и сообщения неизвестного MAX Web вида
приходят пометкой «📍 Геопозиция — открой в MAX» и т. п.

Все сетевые захваты (`stickerUrls`/`voiceUrls`/`videoUrls`/`documentUrls`)
**тегируются `chatId`** на момент захвата — медиа из одного чата не может быть
ошибочно отдано в другой (фикс H5).

## 3а. Реакции и эмодзи

**Как MAX рисует эмодзи.** В тексте сообщения эмодзи — это картинка
`<span class="emoji"><img alt="😀">`, анимодзи — `<span class="animoji"
data-lexical-animoji-emoji="🔥">` с Lottie внутри, сообщение из одних эмодзи
показывается крупно в `.emojis`. Раньше мост брал текст через `textContent` (эмодзи
пропадали: «Привет 😀» приходило как «Привет») и принимал первую `<img>` пузыря за
вложение — текст с эмодзи уходил в Telegram «фотографией» эмодзи, а текст с анимодзи
(у него `img` с `data:`-адресом) вообще не доставлялся. Теперь эмодзи читаются из
`alt`/атрибутов и остаются в тексте, а картинки эмодзи и реакций никогда не считаются
медиа.

**Идентификатор пузыря** — отпечаток автор|время|текст|медиа. Время MAX пишет в
строке `.bubbleContent > .meta` (а не в `.time[aria-label]`, которого в пузыре нет),
поэтому раньше в отпечатке времени не было, и текст, повторяющий любое прежнее
сообщение чата («Ок» сегодня после «Ок» на прошлой неделе), считался уже доставленным
и терялся. Теперь время берётся из строки meta; сама эта строка (и имя отправителя над
пузырём в группе) в текст сообщения больше не попадает — раньше фото без подписи
приходило с подписью «12:04». Переход без повторной пересылки истории: у каждого
пузыря есть и его прежний идентификатор; при первом чтении чата после обновления
пузыри, известные под прежним, записываются под новым (со ссылкой на своё сообщение в
Telegram — ответы и реакции работают), дальше прежний идентификатор учитывается только
выше самого нового пузыря, известного под новым, и не дольше недели. Непрочитанные
сообщения (по счётчику MAX) под прежним идентификатором не узнаются никогда — они новые,
даже если повторяют старое «Ок», — как и сообщение, доставку которого уже пробовали.

**Переименованный чат.** Пока чат открыт, адрес страницы MAX — `/<id>` (настоящий id
чата; в самой странице его нет). Мост берёт id только если адрес сменился вместе с
переключением чата; если открыли другое имя, а адрес остался прежним (MAX переименовал
открытый чат), мост открывает другой чат и возвращается. Чат с уже известным id под новым
именем продолжается в своей теме; его сообщения узнаются под старым именем только по
точному идентификатору (с временем).

**Статичные анимодзи (`MAX_STATIC_ANIMOJI=true`).** Анимодзи и реакции MAX рисует
Lottie-анимацией на `<canvas>`, а canvas не говорит, какой это эмодзи. Пока анимация
грузится, MAX показывает обычную картинку эмодзи с `alt`. Скрипт, который мост
ставит в страницу до её загрузки, отдаёт плееру MAX пустой ответ вместо Lottie-JSON
анимодзи — и MAX навсегда оставляет эту картинку. Сам запрос в сеть уходит как
обычно; стикеры (адреса `...lottie=true`) не трогаются и остаются анимированными.
Побочный эффект — меньше нагрузки на CPU.

**Реакции MAX → Telegram.** Реакции пузыря — кнопки `.reaction` в контейнере
`.reactions` внутри пузыря (медиа) или сразу после него (текст); своя реакция
помечена `.reaction--active`, число — в `.counter`. На каждом опросе мост
сравнивает реакции **других людей** (свою не считает — если она поставлена из
Telegram, она там уже есть) с тем, что уже показано, и ставит боту в Telegram одну
реакцию — самую частую из тех, что бот вправе ставить. Эмодзи, которых нет в списке
реакций Telegram, заменяются ближайшими (😂 → 🤣, 😮 → 🤯, цветные сердца → ❤);
если замены нет — ничего не ставится.

**Реакции Telegram → MAX.** Реакция владельца на пересланное сообщение (или на своё,
отправленное в MAX) ставится в MAX от его имени: клик по уже существующей кнопке с
этим эмодзи, иначе меню сообщения (правый клик, запасной путь — кнопка «Message
actions») и в нём нужная реакция, при необходимости раскрыв полный список
(`.extendBtn`). Снятие реакции снимает её и в MAX. В MAX у человека одна реакция на
сообщение, поэтому из нескольких (Telegram Premium) берётся последняя. Если такой
реакции в MAX нет — пробуются её «родственники» (🤣 → 😂), а если и их нет, бот
коротко сообщает в том же чате, какие реакции доступны (не чаще раза в 10 минут на
случай).

Бот получает `message_reaction` только как администратор группы (в группе с темами
он и так администратор) и только от владельца; реакции других людей и ботов
игнорируются. Выключить всё — `SYNC_REACTIONS=false`.

## 4. Конфигурируемые селекторы (`.env`)

Веб-интерфейс MAX может меняться; все ключевые селекторы переопределяются без
правки кода:

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `MAX_SELECTORS_ATTACH_BUTTON` | `button[aria-label="Upload file"]` | открыть меню вложений |
| `MAX_SELECTORS_ATTACH_MENU_MEDIA` | `button[role="menuitem"][aria-label*="Photo"]` | пункт «Photo or video» |
| `MAX_SELECTORS_ATTACH_MENU_FILE` | `button[role="menuitem"][aria-label*="File"]` | пункт «File» |
| `MAX_SELECTORS_ATTACH_PREVIEW` | `[data-testid="composer"] img, …` | признак прикреплённого вложения |
| `MAX_SELECTORS_OUTGOING_BUBBLE` | `[data-bubbles-variant="outgoing"]` | подсчёт исходящих для проверки доставки |
| `MAX_SELECTORS_SEND_BUTTON` | `button[aria-label="Send message"]` | кнопка отправки |
| `MAX_SELECTORS_MESSAGE_REPLY_BUTTON` | `button[aria-label="Reply"]` | кнопка «Ответить», появляющаяся при наведении на пузырь (путь Telegram→MAX reply) |
| `MAX_SELECTORS_COMPOSER_REPLY_ACTIVE` | `[data-testid="composer"] button.close` | признак включённого режима ответа: крестик на баннере цитаты (им же режим отменяется) |
| `MAX_SELECTORS_MESSAGE_META_TIME` | `.bubbleContent > .meta` | строка времени пузыря («12:04», «ред.»): время идёт в идентификатор, в текст — нет |
| `MAX_SELECTORS_MESSAGE_SENDER` | `.bubbleContent > .header` | имя отправителя над пузырём в группе (читается его `.name`) |
| `MAX_SELECTORS_MESSAGE_FILE_CARD` | `.bubbleContent > .attaches > button.container` | карточка файла: имя в `.title`, размер в `.info`, клик скачивает |
| `MAX_SELECTORS_MESSAGE_LINK_PREVIEW` | `.bubbleContent > .share` | карточка превью ссылки — её картинка не фото |
| `MAX_SELECTORS_MESSAGE_REACTIONS` | `.reactions` | контейнер реакций пузыря (внутри пузыря или сразу после него) |
| `MAX_SELECTORS_MESSAGE_REACTION_CHIP` | `.reaction` | кнопка одной реакции; своя помечена `…--active` |
| `MAX_SELECTORS_MESSAGE_ACTIONS_BUTTON` | `button[aria-label="Message actions"], …` | запасной способ открыть меню сообщения (основной — правый клик) |
| `MAX_SELECTORS_MESSAGE_MENU` | `[role="menu"]` | открытое меню (закрывается Escape только когда оно открыто: без меню Escape в MAX закрывает чат) |
| `MAX_SELECTORS_REACTION_OPTION` | `[role="menu"] .reaction, .menuContainer .reaction` | реакции в меню сообщения |
| `MAX_SELECTORS_REACTION_EXPAND` | `[role="menu"] .extendBtn, .menuContainer .extendBtn` | «показать все реакции» |

### Если что-то снова сломалось

Симптом «бот говорит успех, но фото/стикер не доходит» почти всегда означает, что
MAX поменял вёрстку. Диагностика:

1. Включить debug-скриншоты: `sendFile` сам пишет `after-file-accept`,
   `attach-not-staged`, `after-send` в `logs/diagnostics/`.
2. Сверить актуальные `aria-label`/`role` пунктов меню и атрибут
   `data-bubbles-variant` исходящих сообщений в свежем HTML-дампе.
3. Переопределить соответствующий `MAX_SELECTORS_*` в `.env` — пересборка кода не
   нужна, достаточно пересоздать контейнер.
