**Известные ограничения P0:**
- Стикеры не рендерятся в headless для не-контактов (WebGL/Lottie) — снято переходом на Xvfb (см. `scripts/start.sh`, требуется `MAX_HEADLESS=false`)
- Селекторы могут сломаться при обновлении Max Web интерфейса
- **Идентификация чатов по title (не по стабильному ID)** — у строк списка чатов в MAX нет id-атрибута, поэтому id чата = его название. **Переименования** с 26.09 распознаются: настоящий id чата MAX есть в адресе страницы (`/<id>`), и чат, появившийся под новым именем с уже известным id, продолжается в своей теме. **Два одноимённых чата** по-прежнему сливаются в одну сущность (переписка двух людей попадёт в одну тему) — при коллизии в логе громкое предупреждение. Полный переход на id из адреса (открывать чат по id, а не по названию) — P3 «Chat fingerprint»
- Идентичность медиа нельзя строить на URL: MAX отдаёт подписанные CDN-ссылки, которые пересоздаются при каждой загрузке страницы (см. `docs/MEDIA_PIPELINE.md`)

## P1: Расширенная Карточка Контакта

**Статус**: Не начато (разметка MAX Web изучена 26.09 — см. «Задел» ниже)

### Цель

Каждый Telegram topic должен ясно показывать, с кем пользователь общается. Это снижает риск путаницы при похожих именах.

### Пользовательский Сценарий

При связывании Max-чата с Telegram topic, бот отправляет расширенную карточку:

```text
MAX contact

Name: Иван Петров
Type: personal chat
Phone: +7 000 000-00-00 — если виден
Username: @... если виден
Max chat id: ...
Last verified: 2026-06-11 12:30 UTC

Safety:
Messages in this topic are routed only to this Max chat.
If the active Max chat cannot be verified before sending, the message is not sent.
```

### Изменения В БД

Добавить поля в `chats` или создать таблицу `contact_profiles`:

- `max_chat_id`
- `display_name`
- `chat_type`
- `phone`
- `username`
- `avatar_url` / `avatar_path` / `avatar_hash`
- `profile_fingerprint`
- `last_verified_at`
- `metadata`

Расширить `chat_mappings`:

- `pinned_card_message_id`
- `pinned_card_updated_at`
- `topic_icon_color`
- `topic_icon_custom_emoji_id`

### Новые Max Web Selectors

- `MAX_SELECTORS_CHAT_AVATAR`
- `MAX_SELECTORS_ACTIVE_CHAT_AVATAR`
- `MAX_SELECTORS_ACTIVE_CHAT_META`
- `MAX_SELECTORS_PROFILE_BUTTON`
- `MAX_SELECTORS_PROFILE_NAME`
- `MAX_SELECTORS_PROFILE_PHONE`
- `MAX_SELECTORS_PROFILE_USERNAME`
- `MAX_SELECTORS_PROFILE_AVATAR`

### План Реализации

1. Извлекать avatar и profile metadata при чтении списка чатов
2. Сохранять profile metadata в SQLite
3. При создании topic отправлять avatar photo
4. Отправлять contact card message с route metadata
5. Закреплять карточку с `disable_notification=true`
6. Сохранять `pinned_card_message_id`
7. Обновлять карточку при изменении name/avatar/fingerprint
8. Если закрепление не удалось — предупреждение в личный чат владельца

### Правила Безопасности

- Pinned card НЕ является источником правды для routing (это SQLite)
- Если profile identity изменился — не перезаписывать молча, а сообщить владельцу

### Задел (26.09.2026, по коду MAX Web; на живом аккаунте не проверено)

- **Id чата**: адрес страницы `/<id>` открытого чата (уже используется — переименования).
- **Аватар**: всегда `<img class="avatarImage">` — в списке чатов `button.cell > div.avatar img.avatarImage`, в шапке открытого чата `h2#main-header-title + .header .image img.avatarImage`. `src` — CDN-адрес фото (размер задаётся `fn=sqr_<N>`), либо `data:image/png` с инициалами (фото нет), либо заглушка для удалённого аккаунта. Картинка появляется только когда аватар был на экране.
- **Тип чата** — по подзаголовку шапки `h2#main-header-title + .header .subtitleWrapper`: «N подписчиков» — канал, «N участников» / «… в сети» — группа, «Бот» — бот, «В сети» / «был(а) …» — личный; канал в списке помечен пустым `span[aria-label="канал, "]`.
- **Профиль**: кнопка `h2#main-header-title + .header button.main` («Открыть профиль {имя}») открывает панель `main header.header` (имя, статус, аватар 96px); закрывать кнопкой `button[aria-label="Перейти назад"]`, **не Escape** — без истории Escape закрывает весь чат. Телефон виден только если он есть у контакта в MAX.

## P1: Начать Новый Max-Чат Из Telegram

**Статус**: Не начато (разметка поиска MAX Web изучена 26.09 — см. «Задел» ниже)

### Цель

Дать пользователю возможность начать новый Max-диалог из Telegram без открытия Max вручную.

### Пользовательский Сценарий

```text
/new +70000000000
```

или:

```text
/new Иван Петров
```

Бот возвращает кандидатов:

```text
Найдены контакты:

1. Иван Петров · +7 000 000-00-00
2. Иван Работа · телефон не виден

[Открыть 1] [Открыть 2] [Отмена]
```

После подтверждения:

1. Max Web открывает выбранный чат
2. Активный чат проверяется
3. Создается Telegram topic
4. Создается закрепленная contact card
5. Пользователь пишет первое сообщение в новом topic

### Изменения В БД

Создать `contact_search_sessions`:

- `id`
- `telegram_chat_id`
- `telegram_thread_id`
- `query`
- `status`: `pending`, `confirmed`, `cancelled`, `expired`
- `candidates_json`
- `created_at`
- `expires_at`
- `selected_candidate_id`

### Новые Max Web Selectors

- `MAX_SELECTORS_SEARCH_BUTTON`
- `MAX_SELECTORS_SEARCH_INPUT`
- `MAX_SELECTORS_SEARCH_RESULT`
- `MAX_SELECTORS_SEARCH_RESULT_TITLE`
- `MAX_SELECTORS_SEARCH_RESULT_META`
- `MAX_SELECTORS_SEARCH_RESULT_AVATAR`
- `MAX_SELECTORS_SEARCH_RESULT_OPEN_BUTTON`

### План Реализации

1. Команда `/new <phone|name>` — только в личном чате владельца или в теме General
2. Открыть Max search под browser lock
3. Ввести query и дождаться результатов
4. Извлечь candidates
5. Отправить Telegram inline keyboard
6. При подтверждении — открыть Max result
7. Проверить active chat identity
8. Создать mapping и topic
9. Создать pinned contact card
10. Сообщить пользователю о новом topic

### Правила Безопасности

- Не отправлять текст как часть `/new`
- Sessions должны истекать по времени
- Даже один результат требует подтверждения
- Если active chat нельзя подтвердить — не создавать route

### Задел (26.09.2026, по коду MAX Web; на живом аккаунте не проверено)

- **Поле поиска**: `aside[aria-labelledby="aside-header-title"] .search input.field` (placeholder «Найти»), обычный ввод с клавиатуры; очистка — `aside .search button[aria-label="Очистить"]`. Поиск сбрасывается сам при открытии чата.
- **Результаты** — плоский список `aside .searchResultsList > button.item`: сначала свои чаты, потом «Глобальный поиск» (до 5, контакты и публичные чаты), потом «Сообщения». Имя — `.cell > .title .name .text`. Результаты догружаются: выбирать, когда список не меняется ~1 с. «Ничего не нашли» — `div.empty`.
- **По номеру**: для запроса-телефона (`+7…` или `8…`, полностью) первым идёт пункт «Найти по номеру»; клик открывает чат с контактом и переключает боковую панель на вкладку «Контакты» (её пункты — `a.cell[href="/<id>"]`, id чата прямо в ссылке); вернуть вкладку «Чаты» — через `nav[aria-label="Папки и профиль"]`. Не найден — окно «Не нашли номер».
- После открытия id нового чата — в адресе `/<id>`, имя — в `#main-header-title` («Окно чата с {имя}»).

## P2: Ответы Telegram→MAX (Обратное Направление)

**Статус**: Выполнено 03.07.2026 (см. P0 таблицу выше).

- **v1** (01.07.2026) — ответ пользователя в Telegram topic на текстовый MAX-оригинал отправляется в Max как настоящий reply (бот находит пузырь в MAX Web по отпечатку автор/время/текст и жмёт «Ответить»).
- **v2** (03.07.2026) — добавлены ещё два случая:
  - Ответы на **медиа-оригиналы** (фото/видео и т.д.), пришедшие из MAX: резолвятся по стабильному CDN-токену (`r=` параметр), а не по URL целиком, так как MAX может отдавать разные размеры одной и той же картинки.
  - Ответы на **свои же ранее отправленные** из Telegram текстовые сообщения: сразу после отправки текста в MAX бот дополнительно считывает отпечаток только что созданного своего пузыря (`getLastOutgoingFingerprint`) и сохраняет его в БД (`max_fingerprint`), чтобы последующий ответ на это же сообщение мог найти и процитировать его в MAX.

Оба случая, как и v1, best-effort: если бот не смог найти нужный пузырь в MAX Web (например, он проскроллен слишком далеко), сообщение всё равно уходит, но без цитаты — вместо ошибки.

- **v3** (26.09.2026) — ответы и реакции на **свои же отправленные файлы и фото**: после отправки запоминается CDN-токен своего пузыря (`getLastOutgoingMediaFingerprint`).

### Закрыто 26.09.2026

- ~~`findAndHoverMessage` возвращает самое новое совпадение по отпечатку~~: одинаковые пузыри в одну минуту нумеруются (`#d2`), а поиск пузыря идёт через тот же разбор страницы, что и чтение, — ответ и реакция попадают в нужный.

## P2: Онбординг Без Доступа К Серверу

**Статус**: Выполнено 31.07.2026

Раньше первый запуск требовал найти свой Telegram user id (@userinfobot), выловить id
группы через `getUpdates` и войти в MAX через noVNC по SSH-туннелю — причём последнее не
работало вовсе: VNC-инструменты в образ никогда не устанавливались.

Теперь:

| Шаг | Как это работает |
|-----|------------------|
| Установка | `sh scripts/install.sh` — спрашивает только токен бота от @BotFather |
| Владелец | При пустом `TELEGRAM_OWNER_ID` мост печатает в логи одноразовый код (8 случайных байт в base64url) и ждёт `/pair <код>` в личном чате; после 5 неверных попыток код перевыпускается. До привязки бот не выполняет ни одной другой команды ни от кого |
| Вход в MAX | `getSessionState()` определяет состояние страницы структурно, `captureLoginQr()` снимает QR и присылает его владельцу в личку; код обновляется в том же сообщении по мере ротации (~2 мин), после входа сообщение удаляется. Дедлайна нет — ожидание длится сколько нужно, с напоминанием не чаще раза в 30 минут; повторный запуск цикла — `/login` |
| Группа-релей | `my_chat_member`: добавление бота админом в супергруппу с Темами и есть настройка; при отсутствии Тем или прав бот объясняет это прямо в группе. Группа, куда бота добавили до `/pair`, запоминается и подключается после привязки — с проверкой, что владелец в ней состоит. `/relay` в нужной группе перенаправляет мост туда |
| Хранение | Владелец и группа сохраняются в `settings`; переменные окружения имеют приоритет над найденными значениями |
| Сообщения до входа | Telegram-сообщение, пришедшее пока MAX не подключён, получает ответ «MAX ещё не подключён — сообщение НЕ отправлено» вместо тихой пометки failed |

Безопасность: QR — это учётные данные (кто отсканирует, тот привяжет устройство к
аккаунту MAX), поэтому он уходит только в личный чат владельца, никогда в группу, и
удаляется после входа. Пока открыта форма входа, диагностика не делает скриншот, а
содержимое `<svg>` вырезается из всех HTML-дампов (даже при `DIAGNOSTIC_REDACT_TEXT=false`):
QR нарисован инлайновым SVG, а `/diagnostics` выгружает дампы в тот чат, откуда его позвали.

Побочный эффект: `handlePollFailure` теперь отличает разлогиненную сессию от сломанного
браузера — перезапуск Chromium не чинит выкинутый аккаунт и раньше давал бесконечный
цикл рестартов.

## P2: Retry Policy Для Delivery

**Статус**: Выполнено 26.09.2026 (кроме backoff)

## P2: Работа Без Cron

**Статус**: Выполнено 26.09.2026

Раньше контейнер перезапускался внешним cron каждые 2 часа из-за роста памяти Chromium.
Причины утечки найдены и устранены (неосвобождённые `ElementHandle`, безлимитный буфер
сетевых ответов DevTools); страховка — внутри процесса: перезагрузка вкладки MAX,
перезапуск Chromium по памяти/времени и сразу после падения, `tini` в образе. Подробнее —
`CHANGELOG.md`.
