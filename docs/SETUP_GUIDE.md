# Пошаговая Инструкция По Настройке

Полная инструкция для тех, кто впервые разворачивает проект max-in-tg. От создания Telegram бота до работающего моста.

Вся настройка после установки происходит в Telegram. Свой user ID, ID группы и первый вход в MAX через VNC искать и настраивать больше не нужно: владелец назначается командой `/pair`, вход в MAX делается сканированием QR-кода с телефона, а группа определяется сама в момент добавления бота (если бот уже в группе — командой `/relay`).

## 1. Что Нужно Перед Началом

Перед началом убедись, что у тебя есть:

- **Telegram аккаунт** — обычный аккаунт с номером телефона
- **Max аккаунт** — зарегистрированный на max.ru (ранее oneme.ru), и приложение MAX на телефоне (им ты отсканируешь QR)
- **Второй экран для QR** — код приходит в Telegram, а сканировать его надо камерой телефона из приложения MAX. Заранее открой Telegram Desktop или web.telegram.org на компьютере (подойдёт планшет или второй телефон) — с него и будешь сканировать. Один телефон сам себя не отсканирует
- **VPS сервер** — Debian 12 или 13, **минимум 2 ГБ RAM и ~10 ГБ свободного диска**, архитектура x86_64/amd64 (готовый образ есть и для arm64, но на живом arm64-сервере он не проверялся). Внутри контейнера работает настоящий Chromium под виртуальным дисплеем; если образ приходится собирать на месте, в нём ещё компилируется better-sqlite3, и на 1 ГБ сборка обрывается с `Killed` и `exit code: 137`. Docker ставить заранее не нужно, это шаг 3.2
- **SSH доступ** — умение подключаться к серверу по SSH

Проверить сервер (после первого же подключения по SSH):

```bash
free -h      # строка Mem, колонка total — не меньше 2 ГБ
df -h /      # колонка Avail — не меньше 10 ГБ
uname -m     # x86_64
```

Если тариф ровно 2 ГБ, добавь swap **до** установки — сборка идёт впритык:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Единственное значение, которое придётся ввести руками, — токен бота из шага 2.

## 2. Создание Telegram Бота

### 2.1 Открой BotFather

1. В Telegram найди бота **@BotFather** (с верифицированной галочкой)
2. Напиши ему `/start`

### 2.2 Создай нового бота

1. Отправь `/newbot`
2. BotFather спросит имя бота — введи любое, например: `Max Telegram Bridge`
3. BotFather спросит username бота — введи уникальное имя, например: `my_max_bridge_bot`
   - Username должен заканчиваться на `bot` или `_bot`
4. BotFather пришлёт **токен бота** — выглядит как `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`

### 2.3 Сохрани токен

**Сохрани токен в надёжном месте!** Его спросит установщик.

Пример токена:

```
7123456789:AAHk-zZxXyYwWvVuUtTsSsRrQqPpOoNnMmLlKkJiIhHgG
```

Токен — это полный доступ к боту: не публикуй его и не пересылай. Если он утёк, в @BotFather есть `/revoke`. После `/revoke` старый токен мгновенно перестаёт работать, и мост уходит в бесконечный перезапуск с `401: Unauthorized` в логах: впиши новый токен в `.env` и выполни `docker compose up -d --force-recreate` (именно recreate — `restart` не перечитывает `.env`, подробности в §10).

Список команд в меню «/» бот публикует сам при первом запуске — в BotFather для этого ничего настраивать не нужно.

## 3. Подготовка VPS

> **Root или обычный пользователь?** Провайдер даёт либо root, либо пользователя вроде `debian`, `ubuntu`, `admin` — смотри его письмо. Команды ниже написаны для root. **Если ты не root:**
>
> - подключайся под своим пользователем: `ssh debian@ТВОЙ_IP`;
> - добавляй `sudo ` ко всем командам разделов 3 и 13 (`sudo apt update`, `sudo ufw ...`);
> - один раз разреши себе Docker и **перезайди по SSH** — без нового логина группа не применится, и установщик остановится на «The Docker daemon is not reachable»:
>
> ```bash
> sudo usermod -aG docker $(whoami)
> exit
> # зайти заново и проверить:
> docker run --rm hello-world
> ```
>
> - клонируй проект в свой домашний каталог, а не в `/home`: `cd ~` вместо `cd /home`. Тогда в разделах 11–13 вместо `cd /home/max-in-tg` используй `cd ~/max-in-tg`;
> - сам установщик через `sudo` запускать **не** нужно.

### 3.1 Подключение по SSH

```bash
ssh root@ТВОЙ_IP
```

SSH уже встроен в Windows 11 (Win+X → «Терминал»), PuTTY не нужен. Вход по ключу вместо пароля: `ssh -i C:\Users\ИМЯ\Downloads\key.pem root@ТВОЙ_IP`.

Три вещи, которые пугают при первом подключении, но нормальны:

- при первом подключении спросит `Are you sure you want to continue connecting (yes/no/[fingerprint])?` — ответь **yes** целиком, одна буква `y` не подойдёт;
- **пароль не отображается при вводе** — ни звёздочек, ни точек, курсор стоит на месте. Печатай или вставляй вслепую и жми Enter;
- `WARNING: UNPROTECTED PRIVATE KEY FILE!` на Windows чинится не `chmod`, о котором пишут все руководства, а так:

```
icacls C:\Users\ИМЯ\Downloads\key.pem /inheritance:r /grant:r "%USERNAME%:R"
```

Получилось, когда приглашение сменилось на `root@имя-сервера:~#`.

### 3.2 Установка Docker и Git

```bash
apt update
DEBIAN_FRONTEND=noninteractive apt upgrade -y
apt install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sh

# Проверка — обе команды должны напечатать версию
docker --version
docker compose version
```

Должно получиться примерно так:

```
Docker version 27.3.1, build ce12230
Docker Compose version v2.29.7
```

- `curl` и `git` ставятся **первой** командой не случайно: на минимальных образах Debian их нет, а без `curl` строка с `get.docker.com` молча не выполнится.
- `docker compose version` должен показать **v2.x**. Если пишет `is not a docker command` — поставь плагин: `apt install -y docker-compose-plugin`.
- **Не ставь Docker через `apt install docker.io docker-compose`** — это Compose v1, установщик его не примет и остановится на «'docker compose' (Compose v2) is not available».
- Если `get.docker.com` отвечает `Unsupported distribution`, ставь из официального репозитория: <https://docs.docker.com/engine/install/debian/>.
- Если `apt upgrade` всё же покажет синий или фиолетовый полноэкранный вопрос («Which services should be restarted?», «Configuration file … modified») — ничего не меняй: Tab, затем Enter. Если обновилось ядро, выполни `reboot` и зайди по SSH заново; контейнер после перезагрузки поднимется сам.

### 3.3 Настройка firewall (необязательно)

Шаг необязательный: мост наружу ничего не слушает — в `docker-compose.yml` нет секции `ports`. Если всё же настраиваешь firewall:

```bash
apt install -y ufw
ufw allow 22/tcp        # ЕСЛИ твой SSH на другом порту — открой его: ufw allow 2222/tcp
ufw --force enable      # без --force спросит «Proceed with operation (y|n)?» и подвиснет
ufw status
```

Порт указывай номером, а не именем профиля. Проверь, на каком порту ты сидишь: `ss -tlnp | grep sshd`.

**Не закрывай текущее окно терминала.** Открой второе и подключись `ssh root@ТВОЙ_IP` ещё раз. Не получилось — вернись в первое окно и выполни `ufw disable`.

## 4. Установка

Репозиторий публичный, поэтому ни ключей, ни токенов для клонирования не нужно —
`git` и `curl` уже установлены в §3.2:

```bash
cd /home
git clone https://github.com/GoPro3400/max-in-tg.git
cd max-in-tg
sh scripts/install.sh
```

Что будет происходить дальше:

- **Установщик общается по-английски.** Он спросит `Bot token (input hidden):` — **введённый токен не отображается вообще, ни звёздочек, ни точек**. Вставь ровно один раз (Ctrl+V; в Windows Terminal работает и правый клик) и нажми Enter. Вставишь дважды — получишь «That does not look like a Telegram bot token».
- **Первый запуск идёт несколько минут**: скачивается готовый образ (около 2 ГБ), и в терминале подолгу может ничего не меняться. Если скачать не получилось, установщик напишет об этом и соберёт образ сам — тогда это 5–20 минут. И то и другое нормально, не жми Ctrl+C.
- Чтобы обрыв связи не убил установку на середине, запусти её в `screen`:

  ```bash
  apt install -y screen
  screen -S install
  sh scripts/install.sh
  # оборвалось — переподключись по ssh и вернись: screen -r install
  ```

- **Повторный запуск безопасен:** существующий `.env` не перезаписывается, токен повторно не спрашивается, `data/` не трогается.

Установка удалась, когда внизу появился блок «Almost there. Finish it in Telegram:» с готовой строкой `Send exactly:   /pair <код>` — эта строка нужна в следующем шаге.

Если мост уже работал раньше, повторный запуск может закончиться словами «no pairing code appeared within 180s» — это не поломка, а следствие того, что установщик ищет в свежих логах код привязки, которого у привязанного моста нет. Проверь `docker compose ps` (должно быть `Up`) и `/status` в Telegram; `docker compose down` делать **не** нужно.

## 5. Привязка Владельца — `/pair`

Мост запустился, но пока не знает, кто его хозяин, и поэтому не слушается никого. Привязка — это одно сообщение боту в Telegram.

Нужно три вещи, и вот откуда каждая берётся:

| Что | Откуда берётся |
|---|---|
| **Куда писать** | Личный чат с **твоим** ботом. Ссылку `t.me/…` прислал @BotFather в шаге 2, либо найди бота поиском по username оттуда же |
| **Что писать** | Команда `/pair`, пробел, код |
| **Код** | Его напечатал установщик — **последним экраном**, сразу после запуска контейнера. Если экран уехал, код есть в логах (ниже) |

### 5.1 Возьми код из вывода установщика

Последнее, что печатает `install.sh`, выглядит так:

```
Almost there. Finish it in Telegram:

  1. Open a private chat with your bot (the @username @BotFather gave you)
     and press Start.
  2. Send exactly:   /pair XLTfFu-FQrk
  3. The bot answers with a QR code for MAX. On your phone:
     MAX -> Settings -> Devices -> link a device -> scan it.
```

Код — это то, что стоит после `/pair` во второй строке: в примере `XLTfFu-FQrk`. У тебя он будет другой.

### 5.2 Открой чат с ботом и нажми Start

**Бот на Start не ответит — так и должно быть.** Пока у моста нет владельца, он игнорирует вообще всё, кроме `/pair`: иначе любой, кто нашёл бота поиском, мог бы им управлять. Молчание здесь не поломка.

### 5.3 Отправь код одним сообщением

```
/pair XLTfFu-FQrk
```

Отправлять **только в личном чате** — в группе команда будет молча проигнорирована.

Что ответит бот:

| Ответ | Что это значит |
|---|---|
| `✅ Готово, ты владелец этого моста` | Готово, переходи к шагу 6 |
| `Код не подходит` | Опечатка или код устарел (перезапускался контейнер) — возьми свежий из логов, см. 5.4 |
| `Слишком много неудачных попыток` | После пяти промахов этот аккаунт 10 минут не может пробовать `/pair` — подожди и отправь код ещё раз (сам код не меняется) |
| Тишина | Мост уже привязан к другому Telegram-аккаунту, см. §10 «Привязался не тот аккаунт» |

### 5.4 Если экран установщика уехал — код из логов

Выполняй **из каталога проекта** (того, где запускал `install.sh`), иначе Docker ответит `no configuration file provided: not found`:

```bash
docker compose logs --no-color | grep -o '"pairingCode":"[^"]*"' | tail -n 1
```

```
"pairingCode":"XLTfFu-FQrk"
```

Копируй значение **без кавычек**. Полная строка в логе выглядит так — код лежит в поле `pairingCode`, а не в тексте сообщения (там стоит буквальное `<code>`):

```
{"level":40,"time":1785570933243,"pairingCode":"XLTfFu-FQrk","msg":"No TELEGRAM_OWNER_ID configured — send \"/pair <code>\" to the bot in Telegram to claim it"}
```

Мост повторяет эту строку раз в минуту, пока ждёт. Код меняется при перезапуске контейнера и после пяти неверных попыток — действует только **последний**.

> **Почему код вообще нужен.** Непривязанный бот принимает `/pair` от кого угодно, а @username бота ищется поиском Telegram. Выигрышем от подбора был бы QR для входа в твой аккаунт MAX — поэтому код случайный (8 байт), а не короткий числовой, и после пяти промахов перевыпускается. Все неудачные попытки попадают в логи.

После привязки твой Telegram user ID сохраняется в базе моста, и при следующих запусках код больше не запрашивается.

## 6. Вход В Max Web По QR-Коду

Открой Telegram на компьютере — QR придёт туда, а телефон с MAX держи в руках.

После привязки мост запускает на сервере Chromium и открывает web.max.ru. **QR приходит не мгновенно — подожди 1–3 минуты.** Мосту мало один раз увидеть экран входа: он проверяет это несколько раз подряд (до 45 секунд), чтобы не прислать QR для живой сессии. Сначала придёт текст «🔐 Нужен вход в MAX», через несколько секунд — картинка. Перезапускать контейнер в это время не надо.

1. Открой приложение **MAX** на телефоне
2. **Настройки → Устройства → Подключить устройство**
3. Отсканируй QR-код из Telegram

Что происходит дальше:

- Код живёт около 2 минут, и MAX **не** перевыпускает его сам: по истечении он размывает код, пишет «QR-код истёк» и ждёт нажатия кнопки обновления. Бот нажимает её за тебя и подменяет картинку в том же сообщении — сканируй последнюю версию. Если чат с ботом открыт давно, переоткрой сообщение, чтобы увидеть свежий код.
- После успешного входа сообщение с QR **удаляется**, приходит «✅ MAX подключён — мост запускается»
- Ожидание не ограничено по времени: пока входа нет, мосту всё равно нечего делать, поэтому он обновляет QR сколько угодно долго и не чаще раза в 30 минут напоминает, что всё ещё ждёт
- Сообщение с QR случайно удалили — отправь `/login`: бот пришлёт новую картинку отдельным сообщением, цикл входа при этом не прерывается
- Сообщение, отправленное в Telegram до подключения MAX, не пропадает молча: бот ответит «⏳ MAX ещё не подключён — сообщение НЕ отправлено» — отправь его снова после «✅ MAX подключён»
- Та же схема работает и позже: если MAX выкинет сессию, бот пришлёт новый QR сам

> ⚠️ **QR-код — это учётные данные.** Кто его отсканирует, тот подключит своё устройство к твоему аккаунту MAX. Поэтому бот отправляет его **только в личный чат владельца** — никогда в группу-релей, где могут быть другие участники, — и удаляет сразу после входа. Никому не пересылай и не выкладывай скриншоты.
>
> По той же причине, пока на экране открыта форма входа MAX, диагностика **не делает скриншот**, а содержимое `<svg>` вырезается из каждого HTML-дампа — даже при `DIAGNOSTIC_REDACT_TEXT=false`. MAX рисует QR инлайновым SVG, а `/diagnostics` выгружает дампы в тот чат, откуда его вызвали, в том числе в группу.

## 7. Приватная Группа С Topics (Рекомендуется)

Без группы мост работает наполовину: все чаты MAX приходят в личный чат с ботом одним потоком, но **всё, что ты пишешь боту в личку, уходит в ОДИН выбранный чат MAX** — независимо от того, на какое сообщение ты отвечаешь. Текущий получатель виден в `/status` строкой `Fallback selected:`, список чатов — `/chats`, переключение — `/select <номер>`. Поэтому основной сценарий — группа с Темами: там каждый чат MAX получает свою тему и отвечать можно всем.

### 7.1 Создай группу

1. В Telegram нажми **+** (новое сообщение)
2. Выбери **Создать группу** (New Group)
3. Добавь любого своего контакта (потом можно удалить). **Бота на этом шаге не добавляй.**
4. Название группы: любое, например `Max Relay`
5. Нажми **Создать** (Create)

### 7.2 Включи Темы (Topics)

- **iPhone/Android:** открой группу → тап по названию сверху → **Изменить / Edit** (карандаш справа вверху) → переключатель **Темы / Topics** → включи → **Готово / Done**
- **Telegram Desktop:** открой группу → название (панель справа) → **⋮** → **Управление группой / Manage Group** → переключатель **Темы / Topics** → **Сохранить / Save**

После включения группа станет супергруппой-форумом, и в ней появится тема «General» — это нормально.

> ⚠️ **Сначала Темы, потом бот.** Включение Тем превращает обычную группу в супергруппу и меняет её внутренний ID, а автоопределение срабатывает ровно один раз — в момент добавления бота или изменения его прав; Telegram это событие не повторяет. Бот, добавленный раньше, запомнит старый ID и потом скажет «в этой группе не включены Темы», хотя они включены. Право **Управление темами** тоже появляется в списке только после включения Тем.
>
> **Уже добавил бота до включения Тем?** Ничего страшного и переделывать ничего не надо: включи Темы, убедись, что бот администратор, и отправь в группе **`/relay`** — она подключится. Удалять и добавлять бота заново не нужно.

### 7.3 Добавь бота как админа

1. В группе нажми на название группы
2. Нажми **Добавить участников** (Add Members)
3. Найди своего бота по username (например `my_max_bridge_bot`)
4. Добавь его

   Сразу после добавления бот напишет в группу «⚠️ Мне нужны права администратора» — так и должно быть, он ещё не админ. Просто продолжай со следующего пункта: как только выдашь права, он ответит «✅ Эта группа подключена».

5. Нажми на бота в списке участников
6. Выбери **Назначить администратором** (Promote to Admin)
7. Включи права (на этом экране есть ровно эти):
   - ✅ **Управление темами / Manage Topics** — **обязательно**: без него бот не создаст ни одной темы, и сообщения из MAX вообще не будут доставляться
   - ✅ **Закрепление сообщений / Pin Messages** — желательно: без него intro-карточка темы просто не закрепится, мост продолжит работать
   - Остальные (Изменение профиля группы, Удаление сообщений, Блокировка участников, Пригласительные ссылки, Видеочаты, Анонимность, Назначение админов) не нужны

   Переключателей «Send Messages» / «Send Media» на экране назначения админа нет, и искать их не надо: администратор группы всегда может писать и слать медиа — это права участников, отдельный экран.

8. Нажми **Готово** (Save)

### 7.4 Всё

ID группы искать не нужно. Как только бот стал администратором, он сам определит группу и напишет в неё:

```
✅ Эта группа подключена — чаты MAX будут появляться здесь отдельными темами.
```

Если что-то не так, бот тоже напишет прямо в группу:

- **«В этой группе не включены Темы (Topics)»** — включи Темы (шаг 7.2), затем удали бота из группы и добавь заново
- **«Мне нужны права администратора»** — выдай права из шага 7.3; если ты ещё не успел этого сделать, это не ошибка, а ожидаемое сообщение

Порядок шагов 5 и 7 не важен, но обратная связь приходит в разные места:

- **Сначала `/pair`, потом группа** — бот пишет результат прямо в группу («✅ Эта группа подключена» либо что именно поправить). В логах: `Relay group discovered automatically`.
- **Сначала группа, потом `/pair`** — в группе бот молчит: у него ещё нет владельца, и он не знает, можно ли ей доверять. Результат придёт **ответом на `/pair` в личном чате**: «✅ Группа «…» подключена как релей»; туда же попадут и претензии «Кстати: … не включены Темы» / «… без прав администратора». В логах: `Adopted the relay group the bot was added to before pairing`.

⚠️ Группа, добавленная до `/pair`, помнится только до перезапуска контейнера: если он успел перезапуститься раньше, чем ты отправил `/pair`, Telegram событие не повторит — удали бота из группы и добавь заново.

**После подключения группы личный чат с ботом остаётся только для служебного:** `/pair`, вход по QR, `/login`, `/status`. Писать в MAX нужно **внутри темы** нужного чата. Сообщение, отправленное в личку или в общую тему «General», в MAX не уйдёт — бот ответит `This Telegram topic is not linked to a MAX chat`. Это не ошибка установки, а напоминание выбрать тему; команды (`/status`, `/sync`, …) в General работают нормально.

**Переезд в другую группу.** Отправь **`/relay`** в нужной группе (приватная супергруппа с Темами, бот в ней администратор) — она станет релеем. Команда работает и когда релей уже выбран, и слушается только владельца. Уже созданные темы останутся в старой группе. Заходить на сервер и править `.env` или базу для этого не нужно.

Если бот уже в группе, а Темы или права ты выдал позже, автоопределение не сработает: Telegram не повторяет событие. Проще всего удалить бота из группы и добавить заново — либо отправить в ней `/relay`.

## 8. Проверка Через Telegram

Команды можно набирать через меню «/» — бот публикует их список сам при старте.

### 8.0 Чего ждать сразу после настройки

Группа будет пустой — так и задумано. При первом запуске мост помечает всю уже существующую переписку MAX как прочитанную, чтобы не вывалить в Telegram сотни старых сообщений, а темы создаются по мере поступления **новых** сообщений. Чтобы сразу получить темы для всех текущих чатов, отправь `/sync`.

**Проверка «туда-обратно»:**

1. Напиши себе в MAX с телефона (или попроси кого-нибудь написать) — в группе должна появиться тема с этим чатом и сообщение в ней, обычно за несколько секунд.
2. Ответь прямо в этой теме — сообщение должно появиться в MAX. Если мост ещё не готов, он честно ответит «⏳ MAX ещё не подключён — сообщение НЕ отправлено».

### 8.1 Статус моста

```
/status
```

Бот покажет статус bridge:

- `Running: yes` — запущен цикл опроса
- `Chats:` — количество чатов MAX
- `Routes:` — количество созданных тем
- `Fallback selected:` — в какой чат MAX уходят сообщения из личного чата (когда группы-релея нет)
- `Auto topics:` — создаются ли темы автоматически
- `Poll failures:` — счётчик подряд идущих ошибок опроса

`Running: yes` означает только, что цикл опроса запущен — это **не** значит, что сессия MAX жива, а `Chats:` берётся из базы. Живость MAX показывает `/check`: `Chats visible: 0` и строки `FAIL` означают, что MAX разлогинился — пришли `/login`. `Poll failures:` больше нуля — тот же признак.

### 8.2 Проверь Max Web selectors

```
/check
```

Если все проверки OK — bridge работает правильно.

### 8.3 Синхронизируй topics

```
/sync
```

Бот создаст topics для всех Max чатов. Эта же команда снимает блокировку создания тем (см. §10).

### 8.4 Посмотри чаты

```
/chats
```

Бот покажет список чатов MAX. У привязанного чата в скобках стоит `topic`, у непривязанного — `not linked`; `unread` — есть непрочитанные в MAX, `🔇 muted` — чат заглушён через `/mute`. `*` в начале строки — выбранный fallback-чат (используется, только когда группы-релея нет; переключается командой `/select <номер>`).

### 8.5 Проверь статистику доставки

```
/deliveries
```

Бот покажет сколько сообщений доставлено/ошибок.

## 9. Файл `.env` (Тонкая Настройка)

Конфигурация лежит в файле `.env` в корне проекта; токен туда попадает при установке. Остальное можно не трогать. Что полезно знать:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Единственная обязательная переменная |
| `TELEGRAM_OWNER_ID` | Необязательна. Пустая → владелец назначается через `/pair` и сохраняется в базе. Заполненная → фиксирует владельца, `/pair` не запрашивается |
| `TELEGRAM_RELAY_CHAT_ID` | Необязательна. Пустая → группа определяется автоматически при добавлении бота (или задаётся командой `/relay` в нужной группе) и сохраняется в базе |
| `TELEGRAM_USE_TOPICS`, `TELEGRAM_AUTO_CREATE_TOPICS` | Темы для чатов MAX (по умолчанию включено) |
| `LOG_LEVEL` | Оставь `info`. `debug` заметно ускоряет рост памяти в Chromium и раздувает логи |
| `STARTUP_PRIME_EXISTING_MESSAGES` | По умолчанию `true`: при первом запуске (пустая база) старая переписка MAX помечается прочитанной и не пересылается в Telegram |
| `STARTUP_PRIME_CHATS_LIMIT` | `0` = все чаты (рекомендуется). Положительное значение приведёт к тому, что чаты сверх лимита **вывалят** свою историю в Telegram при первом запуске |
| `MAX_HEADLESS` | Должно оставаться `false`: Chromium в образе работает под виртуальным дисплеем Xvfb, иначе не рендерятся анимированные стикеры |
| `MAX_SELECTORS_*` | Селекторы Max Web — правь, если `/check` показал поломку после обновления MAX |
| `DIAGNOSTIC_REDACT_TEXT` | По умолчанию `true`: текст переписки в **HTML-дампах** заменяется маркерами длины. Содержимое `<svg>` вырезается всегда, независимо от этой настройки — иначе в дамп попал бы QR входа в MAX. На **скриншот** настройка не влияет: вне экрана входа он показывает окно MAX как есть, вместе с открытым чатом, а `/diagnostics` выгружает файлы в тот чат, откуда его позвали. Зови `/diagnostics` из личного чата и удаляй файлы после отладки |

Значения из `.env` всегда важнее того, что мост определил сам: если задать `TELEGRAM_OWNER_ID` или `TELEGRAM_RELAY_CHAT_ID`, будут использоваться именно они.

После правки `.env` перезапусти контейнер:

```bash
docker compose up -d --force-recreate
```

`docker compose restart` здесь не поможет: переменные окружения фиксируются в момент создания контейнера, и `restart` их не перечитывает.

## 10. Частые Ошибки

### Бот не отвечает на команды

**Симптом:** `docker compose ps` показывает `Restarting`, а в `docker compose logs --tail=30` повторяется `401: Unauthorized` → токен неверный или отозван в @BotFather.

**Решение:** повторный `sh scripts/install.sh` токен **не** переспросит (он видит в `.env` непустое значение), правь вручную:

```bash
cd /home/max-in-tg
nano .env                          # строка TELEGRAM_BOT_TOKEN=...  (сохранить Ctrl+O, Enter; выйти Ctrl+X)
docker compose up -d --force-recreate
docker compose logs -f
```

Если контейнер в статусе `Up`, а бот всё равно молчит — скорее всего мост ещё не привязан к владельцу: тогда работает только `/pair` в личном чате (шаг 5).

### Привязался не тот аккаунт (бот молчит на `/pair`)

Молчание в ответ на `/pair` значит, что мост уже привязан к другому Telegram-аккаунту (частый случай — на десктопе открыт второй аккаунт). Чужие сообщения бот игнорирует полностью, поэтому даже вежливого «мост уже привязан» ты не увидишь. Владелец хранится в базе, но переменная окружения важнее (см. §9):

1. Узнай свой numeric user id — напиши @userinfobot.
2. На сервере впиши в `.env`: `TELEGRAM_OWNER_ID=123456789`.
3. `docker compose up -d --force-recreate` (именно recreate — `restart` не перечитывает `.env`).

После этого владелец — ты, `/pair` больше не запрашивается.

### Потерялся код для `/pair`

Код живёт в памяти процесса до первой успешной привязки. Забирай последний из логов:

```bash
cd /home/max-in-tg
docker compose logs --no-color | grep -o '"pairingCode":"[^"]*"' | tail -n 1
```

Если контейнер перезапускали или кто-то пять раз ошибся кодом, код будет новый — используй последний.

### QR-код не приходит

**Причина:** мост считает, что сессия MAX жива, либо страница ещё не догрузилась.

**Решение:**

1. Подожди 1–3 минуты после `/pair`: мост несколько раз перепроверяет экран входа, прежде чем прислать QR (§6)
2. Отправь `/login` — бот пришлёт свежий QR, если вход действительно нужен
3. Если бот отвечает «MAX уже подключён» — проверь `/check` и `/status`
4. Если ты ни разу не нажимал **Start** в личном чате с ботом, писать тебе он не может — бот один раз скажет об этом в группе-релее (текстом, без QR). Открой личный чат, нажми Start и отправь `/login`
5. Бот ответил «Сейчас пришлю QR-код», а QR так и не пришёл. Посмотри `docker compose logs --tail=50`: строка `MAX page never settled into a recognisable state` значит, что страница MAX не догрузилась и мост не понял, что на ней. Лечится перезапуском: `docker compose restart`, подожди 2–3 минуты и пришли `/login` снова. Повторяется — `/diagnostics` и в issue

### Сообщение с QR потерялось

Отправь `/login` — бот пришлёт новую картинку отдельным сообщением, даже если цикл входа уже идёт. Само ожидание входа не прекращается: пока никто не вошёл, бот продолжает обновлять QR.

### Группа не подключилась автоматически

**Причина:** не включены Темы, бот не админ, или бота добавили в группу раньше, чем включили Темы и выдали права (Telegram не повторяет это событие).

**Решение:**

1. Прочитай, что бот написал в группе — там указана конкретная причина. Если ты добавил бота **до** `/pair`, в группе он молчит: смотри его ответ на `/pair` в личном чате
2. Включи Темы и выдай права админа (шаг 7), затем удали бота из группы и добавь заново
3. Если подключилась не та группа — отправь `/relay` в нужной
4. Проверь `/status`: `Auto topics: no` значит одно из двух — либо группа-релей не подключена, либо создание тем заблокировано после ошибки, тогда рядом будет строка `Topic creation blocked:`

### Бот не видит сообщения в группе

**Решение:**

1. Чаще всего причина другая: сообщение пишут не в тему конкретного чата MAX, а в «General» или в непривязанную тему — тогда бот отвечает `This Telegram topic is not linked to a MAX chat`. Пиши внутри темы нужного чата (в `/chats` у него должно стоять `topic`)
2. Убедись, что бот — администратор группы: **бот-администратор получает все сообщения независимо от privacy mode**, отключать его не нужно
3. Только если бот по каким-то причинам не админ: @BotFather → `/mybots` → бот → **Bot Settings** → **Group Privacy** → **Turn off**, а затем **удали бота из группы и добавь заново** — на уже существующее членство новая настройка не распространяется

### Темы не создаются — и из MAX вообще ничего не приходит

**Причина:** первая же неудачная попытка создать тему (нет права **Управление темами** или Telegram притормозил при массовом создании) блокирует создание тем целиком. Мост принципиально не сваливает чужие сообщения в общий чат, поэтому просто перестаёт доставлять — при этом выглядит живым.

**Диагностика:** `/status` — строки `Topic creation blocked: <причина>` и `Auto topics: no`.

**Решение:**

1. Выдай боту право **Управление темами / Manage Topics**
2. Отправь `/sync` — блокировку снимает только эта команда

Ничего не потеряно: недоставленные сообщения не помечаются прочитанными и придут после `/sync`.

### Max Web не запускается

**Причина:** заблокирован Chrome profile.

**Решение:**

```bash
docker compose down
docker run --rm -v "$(pwd)/data/chrome-profile:/profile" debian:12-slim \
  rm -f /profile/SingletonLock /profile/SingletonSocket /profile/SingletonCookie
docker compose up -d
```

### Bridge не пересылает сообщения

**Причина:** селекторы Max Web не совпадают с реальным DOM.

**Решение:**

1. Выполни `/check` — он покажет какие селекторы сломаны
2. Выполни `/diagnostics` — бот отправит screenshot и HTML
3. Поправь селекторы в `.env` (переменные `MAX_SELECTORS_*`)

### Стикер пришёл как `[Стикер]`

**Причина:** не удалось снять стикер — ни перехватом из сети, ни кадром с canvas. Это фолбэк, а не поломка: остальные сообщения из этого чата идут нормально.

**Решение:** обычно ничего делать не нужно. Если так приходят *все* стикеры подряд — выполни `/check` и `/diagnostics` и приложи вывод к issue.

## 11. Полезные Команды Docker

### Как вернуться на сервер потом

Закрывать терминал безопасно — мост работает в Docker и переживает и закрытие терминала, и перезагрузку сервера (`restart: unless-stopped`). Чтобы вернуться, открой терминал и повтори две команды:

```bash
ssh root@ТВОЙ_IP
cd /home/max-in-tg
```

Запиши себе IP сервера и пароль (или путь к ключу) — без них вернуться не получится.

### Команды

Все команды ниже выполняются **из каталога проекта**, иначе Docker ответит `no configuration file provided: not found`.

```bash
docker compose ps                      # работает ли мост: STATUS = Up (healthy)
docker compose logs --tail=100         # последние 100 строк
docker compose logs -f                 # следить вживую; выйти — Ctrl+C
docker compose restart                 # перезапустить (НЕ перечитывает .env)
docker compose down                    # остановить
docker compose up -d                   # запустить снова после down
docker compose pull                    # скачать образ новой версии (обновление — §13)
docker compose up -d --build           # только если образ собираешь сам (форк или свои правки)
docker compose up -d --force-recreate  # применить изменения .env
```

**Ctrl+C в `logs -f` выходит только из просмотра логов — мост продолжает работать.** Остановить мост может только `docker compose down`.

`docker compose ps` показывает не только `Up`, но и `(healthy)` / `(unhealthy)`. `unhealthy` значит, что процесс упал или не примонтировался каталог `data/`.

Установщик поднимает мост через `docker-compose.yml` в корне проекта — эти команды работают с ним же. В нём уже заданы лимит памяти (`mem_limit: 2048m`) и ротация логов (10 МБ × 5). Есть ещё hardened-конфиг `docker-compose.prod.yml` (read-only корневая ФС, `cap_drop: ALL`, `no-new-privileges`, `pids_limit`); если запускаешь мост из него, добавляй `-f docker-compose.prod.yml` к каждой команде.

### 11.1 Перезапуск браузера (встроенный, cron не нужен)

Раньше Chromium в контейнере тёк: примерно за 3 часа рендерер вырастал до ~2 ГБ, после чего фото из Telegram в MAX переставали уходить, и это лечилось cron-задачей, которая раз в 2 часа перезапускала весь контейнер. Причины утечки найдены и устранены (мост держал ссылки на удалённые из страницы узлы DOM — каждый опрос «пришпиливал» десятки тысяч узлов, — а DevTools копил тела всех сетевых ответов без ограничения). **Страховка встроена в мост**, настраивать ничего не нужно:

- если все процессы Chromium вместе заняли больше 900 МБ (`MAX_PAGE_RELOAD_MEMORY_MB`), вкладка MAX перезагружается — это несколько секунд;
- если больше 1300 МБ (`MAX_BROWSER_MEMORY_LIMIT_MB`) или браузер работает дольше 6 часов (`MAX_BROWSER_RECYCLE_MINUTES=360`) — Chromium перезапускается целиком, 15–30 секунд. `0` отключает соответствующий триггер;
- всё это происходит между циклами опроса: никогда посреди отправки и никогда во время входа по QR. Сессия MAX сохраняется (она лежит в профиле), Telegram-бот не отключается;
- сообщения из Telegram, отправленные в это время, ждут и уходят сразу после; сообщения из MAX подхватываются следующим опросом;
- в `/status` видно, как давно запущен браузер и загружена страница, сколько занимает память и сколько было перезагрузок и перезапусков (`Browser uptime`, `Browser memory`, `Browser recycles`).

**Если cron-задача у тебя уже настроена по старой инструкции — удали её**, она больше не нужна (и лишний раз отключает бота):

```bash
crontab -l | grep -v 'docker compose restart' | crontab -
crontab -l    # проверить, что строки с docker compose restart больше нет
```

В образ добавлен `tini`: он подбирает завершившиеся процессы Chromium, которые раньше копились «зомби» до перезапуска контейнера.

## 12. Бэкап

Останови мост перед бэкапом — иначе в архив попадёт незавершённая база (SQLite пишет в режиме WAL) и живой профиль Chromium:

```bash
cd /home/max-in-tg
docker compose down
tar czf ~/max-in-tg-backup-$(date +%Y%m%d).tar.gz .env data/
docker compose up -d
```

В `data/` лежит всё, что мост о себе знает: сессия MAX (`chrome-profile/`), владелец, группа-релей и **привязка «чат MAX → тема Telegram»**. Потеряешь `data/` — мост заведёт вторые темы рядом со старыми, а старые останутся мёртвыми.

Бэкап содержит активную сессию MAX и токен бота — храни его как пароль.

Кроме твоего бэкапа мост сам копирует базу (`max-in-tg.sqlite`) перед первым запуском новой версии — в `data/backups/`, три последние копии. Это защита на случай неудачного обновления (см. §13), а не замена бэкапу: в копии нет сессии MAX и токена, но есть база с текстами пересланных сообщений и названиями чатов — храни её как переписку и никуда не пересылай.

### Переезд на другой сервер

1. На **старом** сервере выполни `docker compose down` и не поднимай обратно: один токен нельзя опрашивать двумя контейнерами (Telegram отдаёт апдейты только одному, второй получает 409), а вторая сессия MAX выкинет первую.
2. На новом: `git clone`, распакуй архив в корень проекта (`.env` и `data/`).
3. `sh scripts/install.sh` — он увидит готовый `.env`, токен не спросит и вернёт `data/ tmp/ logs/` владельцу uid 10001.

Ни `/pair`, ни QR при этом не потребуются.

## 13. Обновление проекта

Обновление — две команды, из каталога проекта:

```bash
cd /home/max-in-tg
docker compose pull
docker compose up -d
```

Docker скачает готовый образ новой версии и перезапустит мост (это занимает около минуты). `.env`, `data/` и вход в MAX сохраняются, поэтому ни `/pair`, ни QR заново не нужны.

**Как узнать, что вышла новая версия.** Бот сам напишет в Telegram: раз в сутки он делает один запрос к `api.github.com` за номером последней версии и один раз сообщает о новой, с ссылкой на описание и с этими двумя командами. Больше ничего не отправляется. Отключить: `UPDATE_CHECK=false` в `.env` (затем `docker compose up -d --force-recreate`). Свою версию покажет `/status` (строка `Version:`). Что нового — на странице [Releases](https://github.com/GoPro3400/max-in-tg/releases) и в `CHANGELOG.md`; если для обновления нужно что-то сделать руками, это написано в начале описания релиза.

**Один раз, если ставил до появления релизов** (compose-файл в каталоге ещё старый, без готового образа): сначала `git pull`, потом те же две команды. Дальше `git pull` нужен только когда в описании релиза сказано, что изменился compose-файл или установщик.

**Копия базы.** Перед первым запуском новой версии мост копирует базу в `data/backups/` (файл вида `max-in-tg-0.2.0-to-0.3.0-….sqlite`), хранятся три последние копии. Схема базы обновляется сама при старте.

### Вернуться на прежнюю версию

Если новая версия не понравилась:

1. В `.env` добавь строку с прежней версией: `MAX_IN_TG_VERSION=0.2.0` (можно `0.2` — тогда самая свежая 0.2.x).
2. `docker compose pull`, затем `docker compose up -d`.

Часто этого достаточно: до сих пор схема базы менялась только добавлением нового, и прежняя версия этого не замечает. Если в описании релиза сказано иное, или после отката мост не стартует и ведёт себя странно, верни и базу — той копией, что мост сделал перед обновлением:

```bash
docker compose down
ls data/backups/                                   # выбери копию «…-<прежняя версия>-to-<новая>-…»
cp data/backups/<файл>.sqlite data/max-in-tg.sqlite
rm -f data/max-in-tg.sqlite-wal data/max-in-tg.sqlite-shm
docker compose up -d
```

Копия сделана в момент обновления, поэтому мост не будет знать о том, что доставил после него: часть последних сообщений, которые ещё видны в MAX, может прийти в Telegram повторно.

Закрепил версию и хочешь обновиться? Поменяй `MAX_IN_TG_VERSION` в `.env` на нужную (или удали строку — тогда будет самая свежая) и снова выполни `docker compose pull` и `docker compose up -d`: пока версия закреплена, `pull` новых версий не приносит.

### Если образ собираешь сам

Форк или свои правки: `docker compose up -d --build` собирает образ из каталога проекта (в `docker-compose.yml` для этого есть `build: .`). Копия базы и уведомление об обновлениях работают так же.

После нескольких обновлений на диске накапливаются старые образы:

```bash
docker image prune -f
df -h /
```
